# 首批运行与维护候选

2026-10-27；revision 3；supersedes r2：把抽象维护要求收敛为交付索引、三段接手走查和阶段门槛；前稿项目外保全。proposed／候选设计，非正式产品验收。

## 0. 先看建议和待定项

**建议采用集中服务：Windows软件和手机入口共用正式业务记录、当前权限及规则；原件按版本保管，备份放独立位置。** 不依赖员工电脑常开，每台不各养一份正式数据库；手机轻量网页是候选，不把EXE当手机端。

首批按在线办理作运行基线候选。基础业务由普通程序运行，仍需可用业务／文件／核权底座；AI停用时的人工路径，与断网时本地未提交草稿分开。是否采纳本地保留、允许哪些内容及缓存有效期另定，不承诺完整离线或恢复网络就自动正式生效。

**服务放公司还是获准云地域、谁承接应用维护、恢复目标和费用都未定。** 用户已答维护方尚未确定；不再重问，也不默认实习生／AI值守。开源或租云机不等于没有应用维护成本。

| 位置候选 | 何时值得继续验证 | 故障影响必须怎样核 |
| --- | --- | --- |
| 公司专用受控服务＋远程接入 | 原件／资料需留公司，且有受控主机、供电、网络和实际承接；外出电脑／手机的接入能管理 | 停电／主机故障、公司出口、远程控制／中继及身份服务分别核。公司断外网时内网能否办取决于实际依赖，不能默认仍可用或自动切换 |

位置与承接方式交叉选：内部技术承接、开发＋维保、受管基础设施＋明确应用维护都沿[投入维护r5](../决策与变更/2026-10-27-首批投入量级与维护安排.md)同范围比较。公司、家庭及移动网络的实际目标设备尚未验证，不新增云采购、组网配置或生产访问。

## 2. 故障时员工怎样继续

每条继续能力都以该动作所需底座及当前授权仍可用为前提；不把逻辑模块独立说成物理故障隔离。

| 情况 | 员工／老板应看到什么 | 继续与恢复边界 |
| --- | --- | --- |
| 本机断网／业务服务不可达 | 明确未连接，旧内容有读取时点／版本；若获准且入口能保全，仅留“本地未提交”稿 | 不显示服务端已保存／上报，不离线确认更正／审批或假发任务；回连重核对象／范围／当前权／版再决定提交，本机草稿不证明远端无人改过 |
| 提交后没收到回复 | “结果待核”，保留原操作身份与已知内容 | 先查原操作及当前结果，查不到不直接判未执行，不换键盲重做；成功更正只生效一次，旧回执不复活旧值 |
| 业务库或当前查询不可用／视图迟到 | 暂不可用或旧视图时点／版本，不把空白说成0、未开工／无订单 | 所需业务写入／核权／版本校验不可用时暂停正式办理；仅视图迟到不否认原操作成功，获准时回源查有效版，旧视图不冒作实时，不因未更新再办一次 |
| 原件暂不可读／某件保存未明 | 哪个获准版本不可用、逐件已存／失败／未明，原件与业务状态分开 | 有其他充分依据的获准普通业务可继续；需要该证据的动作停在对应条件，不能偷换同名件、抹有效结果或盲重传整夹 |
| AI／提取或某个搜索分支不可用 | 原件已保存与处理失败分开；说明普通查询实际覆盖范围 | 业务／文件／核权可用时人工补记、按编号／标签／可读文字找回；不承诺未识别音视频／扫描图内文可搜，旧处理晚到不盖新核对 |
| 当前核权不可用／权限变化 | 受影响能力不可核或受控响应；内部原因与中性对外提示分开 | 不沿旧会话／旧索引／旧产物权限放行，不冒作合法空结果；撤权不无条件删除另有许可的正式进展 |

断网、服务故障和权限变化是不同条件；不让员工在不清楚原提交是否成功时靠重新录入“续办”。获准人工过渡及其后续有据补录由适用业务规则决定，不新造统一离线流程或公司审批链。

## 3. 备份与恢复怎样才算完成

候选恢复集合为：一致业务恢复点及历史／原操作结果＋该点所引用的不可变原件／目录清单＋人工修正／核对／来源关系＋匹配应用版本和必要配置。备份访问／恢复所需凭据受控保管，不进普通导出／公开GitHub；具体保管人与位置待落实。

代码仓库、员工按需副本、业务备份各有用途。独立备份位置还需核与主服务共用的主机／磁盘／账号等故障风险，不能只在同一磁盘另建目录就称已隔离；具体故障域和访问边界待定。业务库和文件备份完成时间接近不证明引用闭合；可重建索引不能替代原件／人工修正。实际备份频率、保留、可承受丢失量和恢复耗时目标由业务与承接条件决定，当前不猜“每天一次／十分钟恢复”等数字。

未来恢复按下列顺序核，未执行：

1. 在隔离环境选择明确恢复截止点和匹配版本，保护现有数据，默认停外发及业务副作用。
2. 核业务记录、原件／目录版本清单及字节完整性、人工修正／历史引用；缺件、同尺寸坏件或同名异版逐项标出，不偷换。
3. 对账当前身份／授权依据；旧策略、索引或旧账号不能自动复活权限。未核清保持相应能力受控。
4. 按原操作分清已成功、结果未明和获准可重试任务，核当前版本／资格后再决定，旧队列不全部重放通知或确认。
5. 必要索引在来源／当前权对齐后重建，按选定固定业务场景和产物核对，再按已核条件开放对应能力，留实际恢复点／缺口／结果。

例如，若选定的匹配备份点已包含单甲正式更正为3的成功结果，恢复后应查到局部3、原4替代历史和对应原操作；全单累计仍未知，不能再加一次。若实际只恢复到此前的4，必须说明恢复点及其后缺口，不能声称找回了后来的3或偷偷重办来补齐。

现有证据仅可参考方法：短连接中断／重启及回执、最小顺序台账、静止SQLite＋文件集合限定恢复；整树恢复失败及同快照子树成功、缺件／坏字节负例各按原报告范围。不是当前产品、在线主库跨存储、真实授权恢复或旧任务安全重放通过；本轮没有复跑。

## 4. 谁负责什么，升级和换人怎样接续

以下为责任分界候选，不指定真实人选或新设固定三岗位；能否承担须落实，不能靠四个AI窗口替技术承接。

| 事情 | 公司有权业务责任者需决定／核什么 | 技术承接者需交什么 |
| --- | --- | --- |
| 日常故障与续办 | 受影响业务、获准人工过渡及正式办理边界 | 查原操作和最后可核状态，报告故障范围，按已定预案控制／修复，不靠员工盲重输 |
| 账号／权限／交接 | 本次停用、对象／动作范围和业务接办生效条件 | 落实当前会话／记录／文件／输出访问及历史保留，不自行改归属、确认或金额 |
| 版本升级／失败退路 | 已定业务验收和开放范围，核未完业务影响 | 匹配程序／配置与数据版本，升级前保护、兼容／迁移检查、原操作和旧任务对账；不是给一个新EXE就完事 |
| 备份／隔离恢复 | 可承受缺口、业务结果及当前授权核对，按既定条件决定开放 | 可恢复集合、受控凭据、缺件／坏件和引用核验、实际恢复记录；不能只给“备份成功”截图 |
| 换维护人／退出 | 公司控制的账号／资产、接手与退出范围、资料保留及旧访问处理 | 可接续源码／版本及许可依赖、构建／配置、数据及原件清单、维护记录；新承接在隔离环境实际接续，旧凭据按规则处置 |

技术故障可按已有预授权措施处理，不固定每次再找老板审批；恢复连通不代表业务条件已齐。技术管理不代业务决定；能接触服务器／备份／凭据的实际范围沿权限稿另核。

升级回退须验证程序与数据结构／迁移的兼容；不能默认旧程序能读新结构，也不能拿旧库直接覆盖升级后已发生的新业务。应用、文件、任务及配置的匹配和可恢复退路由实际路线验证后写入交付。

## 8. 交付包与实际接手验收（候选）

**建议以同一发行物、同一套业务例子验交付；接手者离开原作者仍能按说明操作。** 下列是待采用的交付要求，不是现有成品、已签维护合同或已完成试用。主项目尚无可安装交付包，两个项目外实验不改这个状态。

### 8.1 交付索引要指向哪些实物

每次交付先给一个版本索引，记录来源提交／版本、完整配套目录清单／逐件或归档产物SHA256、目标配置身份、兼容环境、适用数据结构版和证据位置；只含这次实际使用的依赖／组件，不把工具箱全数打包给员工。可多目录存放，但索引中的受控位置须由公司批准的接手者实际取得，不靠原作者电脑绝对路径。

| 交付内容 | 至少明确什么 | 怎样核，不以文件存在代替验收 |
| --- | --- | --- |
| 程序与对应源码 | 本次Windows安装产物／配套服务，来源提交、构建步骤和校验值；手机／网页入口按所选路线列出 | 从索引取得对应源码可构建，实际安装和测试的产物与最终交付物一致；服务端／客户端兼容，不拿开发机通过代替员工环境；不要求另一次构建必然逐位同字节，但改包／配置／迁移须重新记身份并复验受影响段 |
| 固定依赖及来源许可 | 直接依赖及随包／运行所需间接依赖版本、锁定／校验方式、来源／许可证及修改／分发范围；模型若本次不用则不纳入必需启动链 | 在约定干净环境按说明取得和运行，保留构建／启动输出及实际依赖；不依赖作者未登记的全局软件，不把研究工具箱当产品安装包 |
| 配置、资产与受控凭据 | 配置模板、公司批准的代码／服务／域名／备份等资产控制、密钥取得／更换方式、必要权限 | 接手者按授权取得并配置，能更换或停用旧接入；公开代码／普通导出不得带公司原件、生产密码或私钥，索引只记录受控位置和责任，不记录秘密本身 |
| 数据结构及变更 | 业务库／原件版本／引用／原操作和结构迁移的匹配版本；升级兼容和数据去向 | 从新空库初始化或按目标旧版迁移，保留前后对账；不能靠作者临时手改表，不能默认旧程序可读新结构 |

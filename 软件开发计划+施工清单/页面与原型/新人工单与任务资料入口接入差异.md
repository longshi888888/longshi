# 新人工单与任务：资料入口接入差异

2026-10-30 · revision 1 · proposed；只做现有设计／源码和资源核对，**未运行新的资料关联或上传**。承接人工卡r8§15、用户两小时连续工作，以及现有资料中心r4／关联走查r3。旧资料模块的有限证据继续有效，不重写为新人工单已经接通。

员工要感受到的是：**在原订单或任务旁找到有权看的资料，看完还在原位置，刚写的字没丢。** 不强制每条任务带附件，也不让员工再次准备已给过的公司资料。

```mermaid
flowchart LR
 F[已保管的具体资料版本] --> O[明确引用到获准订单]
 F --> T[明确引用到已发布任务]
 O --> RO[订单相关资料区]
 T --> RT[任务相关资料区]
 RO --> V[只读所指版本]
 RT --> V
 V --> B[核目标当前权，回原位置]
 D[任务草稿附件] -.现组件未覆盖，不定为公司制度.-> F
```

| 新页面的接入点 | 可复用的实际依据 | 需要补的接缝／不能直接照搬 |
| --- | --- | --- |
| 当前订单 | 新目录有可靠OID及当前读取结果；原related接口按order/task目标和当前权读引用 | 第一轮候选是**整单相关资料**。当前material_refs不含ML行目标，不能把整单附件叫“这条明细独有资料”，也不凭原话关联自动归某行 |
| 当前任务 | 已下发任务有可靠task-ID、publication/version；资料目标读取已核发布者或有效接收者 | 任务接收不授原件读权。正文、回复仍可用，没原件存在性权时不露标题、版本或隐藏数量 |
| 任务尚在草稿 | 资料可先独立保管，现资料目标查询只接task_publications | **这是原实验组件限制，不是公司必须“先下发、再准备附件”的制度。** 如果需要草稿附件，应另定草稿可见性、发布带哪版引用及修改规则；不能为了迎合现组件强改业务 |
| 打开引用版后返回 | 原related.js使用同页dialog，返回只重核目标与刷新资料区，不重建编辑表单 | 新目录只读返回原单不是这个dialog协议。不能用全页重载代替返回，否则可能清稿／重新归属。返回失去目标读权时，要清那个目标的服务投影，保本人稿在原对象，不牵连仍获准的独立任务 |
| 来源／资料失读 | 各区块分别核权；引用固定版本和原件大小／SHA已有旧证据 | 原件单块暂不可读不等整单不可读；真实目标撤权又不同。未存任务回复在“目标撤权→恢复→重开详情”下的恢复还需专门验证，不能把此前正常返回保稿泛称所有草稿通过 |
| PDF等预览 | 旧二进制实验已有小PNG/JPG／两页PDF证据；本机PDF.js已装 | **本轮新根及恢复包code/vendor没有pdf.mjs和pdf.worker.mjs。** 不能据源码哈希或旧成功声称新包PDF预览可用。工具箱现有两文件，只证明资源存在；须明确匹配版本、许可证／依赖及资源清单后，在新入口另验，不在项目内重装 |

接入顺序候选为：先读已有资料的明确引用，再接必要的引用办理；上传、整理、新版和类别上报各沿原职责，不顺便合成一键全部完成。当前文本、截图、PDF的实验限额不定为公司产品限制，视频、语音、文件夹和大文件仍另循原计划。

下一次最少核六件事：选错单不带走资料；引用v1不被新v2替换；只失原件权不清任务正文；失目标权不留旧投影或把稿移到别对象；busy／结果待查时不打开新查看流程；缺预览资源能明确报不可用，不能显示成没有资料。引用失败只处理该引用原操作，不另存一份文件。

本轮证据是现有file_routes.py的target_read／target、related精确读取和related.js返回逻辑，以及本机文件是否存在的核对；没有新增schema、API、关联记录、原件或新预览运行。PDF.js本机包的版本／许可字段及模块、worker SHA另存项目外资源核对记录，不是新采用或许可法律结论。G03、上报类别规则与真实文件范围仍按原暂缺安排；无新问卷。

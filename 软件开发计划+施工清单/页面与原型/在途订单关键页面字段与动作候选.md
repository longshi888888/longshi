# 在途订单关键页面字段与动作候选

2026-10-27；revision 3；supersedes r2：补需求变更请求/生效与实际结果的动作分支；r2保全项目外。历史r2 supersedes r1：按三方指定回读补草稿/订单、接续基线、确认摘要与办理/视图状态；r1保全项目外。1号；proposed。承接[操作与验收草案r2](在途订单操作与验收草案.md)，先细化当前工作台、快速反馈／核对、确认后查看三个相连位置。不是最终数据库字段、权限制度、已实现页面或正式开工批准；没有新组件运行。

## 1. 当前订单工作台：先找到需要处理的事

| 显示内容 | 内容从哪里来／何时显示 | 不能默认成什么 |
| --- | --- | --- |
| 订单识别与客户／需求摘要 | 本系统已建立且当前有权查看的订单；待核需求草稿另有标记和查回入口，不进正式订单统计。显示编号／名称只供辨认，系统关联使用稳定身份 | 同客户或相近规格不证明同一单；无权者不显示隐藏订单的名称、数量或存在性提示 |
| 当前需求及交期 | 获准的当前有效版本；未明确的数量、单位、交期显示待补 | 不填0、今天或推测的承诺日期；待生效变更不替换当前要求 |
| 已确认结果摘要 | 按明细／加工范围／阶段展示有效结果及适当时点 | 不合成一个全单完成比例；“未获更新”不写成“未开工” |
| 待核／异常／待办 | 各自有依据的反馈、争议、质量风险和事项，按当前权限过滤；可同时存在 | 风险已报告不等正式停发；任务待验收不等加工没有发生 |
| 最近更新与覆盖提示 | 分清实际发生、登记／确认及查询数据时点；中途接续保留已知基线覆盖阶段/范围、数量性质、已知截止时点及历史缺口，未知不补造 | 最近上传不是现场最新；不在没有现场依据时承诺秒级实时 |
| 当前／历史用途与筛选 | 当前工作池、已完历史及适用暂停／取消视图可分别查看；查询保持口径 | 归档不改完成状态；重开不让同一单在两个当前集合重复累计 |

接续累计与基线未核兼容时，首报不当从零新增，也不能直接相加；这不阻止先留资料。内部身份不是订单成立证据。

主要动作候选：打开订单、从该订单留反馈、查看本人获准待办、建立／接续记录。每个动作独立核权；“能看”不自动获得建单、确认或更正权。独立资料和普通任务仍有入口，不强制先选订单。

## 2. 快速反馈：只核本次真正需要的内容

| 内容／字段组 | 已有关联订单／任务时 | 自由补记／上传时 | 哪一步才必须明确 |
| --- | --- | --- | --- |
| 本次说明或选取的资料 | 可直接简短补记或选关键片段，不强制文字同时配图 | 任一可保留的关键内容即可开始；原音不存在时明确是本人补记／转述 | 保存须有可保留内容；具体资料接收权限与大小限制仍需对应方案 |
| 订单、明细与工作范围 | 从已核实的具体上下文带出，员工核本次是否适用；全单任务不自动变具体加工范围 | 系统可建议，员工有依据再核对；未知可先不关联 | 资料保存不一律必填；推进相应正式结果前须可靠对应 |
| 变化性质 | 区分实际结果、计划／估计、需求变更、异常或资料补充，尽量利用已有上下文 | 可先原样保存，不要求员工为归档任选一个不理解的默认类型 | 采取相应业务动作前须明确；不同性质不互相推定 |
| 数量、单位和新增／累计含义 | 从可靠来源带出已知部分，只核变化；不按计划上限补实际量 | 只有内容涉及相应数量时才整理，不明显示待核 | 正式数量确认／汇总前须明确，不把所有沟通资料都变成必填数值表 |
| 实际时间与依据性质 | 已知才记录发生时间，区分亲历、转述、原文和估计 | 不知发生时间可保留未知；不能编造原音、录制时间或位置 | 系统自动记录提交／确认时点；期间分析须另有适用时间口径 |
| 来源对照及差异 | 按权查看相关页、格、画面或音频短段；只显示必要差异 | 无附件的人工说明也保留其来源性质，不能假造页码／时间戳 | 核对与确认时保留各字段实际依据；混含受限信息不能因一段可见而开放整件 |

分类及何时算上报沿用按类别决定的方向，不把上表改成所有人统一填写的必填表。系统自动保留版本、操作者和来源关系，不让员工为此重复抄写。

正式确认前给出只含适用项的摘要：订单、稳定明细/具体范围、阶段、数量/单位/新增累计含义，以及所依需求、草稿和业务版本。带出不等于可靠，所依资料需可核且实际必需来源已保管；与本次无关附件失败不一律阻断。后来补交附件不自动改变原确认内容或补造原确认依据，补充/替换另按权与版本办理。

主动作按变化性质分支：实际阶段结果的确认、需求变更请求的提交和需求变更的生效分别说明。变更请求待生效时保留当前需求10和请求12并列；生效核适用权、规则、期望版本及影响，不自动产生加工完成量。不需要的审批不添加，合并办理也须明示实际作用。

### 动作及返回提示候选

| 动作 | 条件与实际作用 | 返回及失败时继续方式 |
| --- | --- | --- |
| 保存资料／补记 | 当前允许接收相应内容；只保管，不默认确认业务或通知到人 | 逐件列保存、未收齐或结果待核；识别失败保留原件，可人工继续 |
| 保存核对进展 | 当前有相应内容核对权，所核草稿基线仍适用 | 仍有关键缺项时明示已保存核对进展及缺项；必要内容已核、仅待正式确认时显示“内容已核对，业务结果待确认”。过期只核差异，保留修改，不强迫整表重录 |
| 核对并确认 | 同人有适用确认权，来源、对象、规则和期望版本齐备 | 业务服务成功后才显示范围结果已确认；无权／缺项／冲突分别给可理解结果，不自动扩大成整单确认 |
| 提交需求变更／使适用变更生效 | 指明原需求版本、差异及适用动作；提交与生效分开判断，可按规则同次明确办理 | 请求待生效不改当前需求，旧审批/反馈的适用影响需核；不顺便改实际加工结果 |
| 修改或更正 | 未生效草稿可按权修改；正式结果须走有依据的更正并保留旧记录 | 旧版本冲突时重新核差异；实际返工另留后来事实，不共用一个“撤回完成”把历史抹掉 |
| 查询本次办理结果 | 已发出但回复未明时，查原操作，并核当前查看权 | 查到原成功则引用原结果；暂查无保留未明，不建议换键新办或强刷伪装失败 |
| 以后再处理 | 保存层次及当前结果已明确，操作者允许暂留 | 留在相应待核列表；仅本机暂存若采用必须明确“未提交”，不能声称主管已收到 |

办理中的本次内容固定；修改另存未提交的后续草稿，未核明原办理前不为同一拟确认事实另发确认。发送前取消与发送后停止等待/离页不同，后者不撤销已生效结果。重进页面查原线索须实现持久恢复及当前权核验，尚未联验。业务已成功但看板尚未追上时，显示“已确认，视图更新中”及快照时点，不让人再确认一次。

按钮名称和组合仍待审。无确认权者不显示可点击的正式确认；有权但条件暂不够时说明缺项。已发请求期间不把本机取消当撤销业务；离开页面后怎样查询未明操作仍须在实现验收中证明。

## 3. 确认后查看：看到同一份有效记录

应显示：适用订单／明细／范围、具体阶段、有效数量和单位（若适用）、来源／确认时点、当前版本，以及独立存在的待核／风险／任务状态。来源链接须另核当前权，不因看得见进度就开放整件附件。

例：只确认范围甲4件加工结果时，显示“甲范围：4件加工结果已确认”；其他范围未获对应更新，检验与出货另看各自依据。任务若需验收仍可显示待验收，通知若重试仍显示待发送／送达待核，不能顺便标员工已读。

老板可以继续提问、按权查看依据或下事项。正式数值由业务服务取数，AI解释不写回正式值；历史页面明确采用当时已知还是按当前更正重算。页面过期或查询失败显示数据时点／不可用原因，不补0或把旧快照标现在。

| 检查情景 | 页面应能证明什么 | 对应既有候选 |
| --- | --- | --- |
| 从具体任务反馈与从全单任务反馈 | 前者核可靠具体范围；后者仍须明确本次局部范围，系统不偷偷补全 | 2号O03—05、3号FB01／04、4号T01／04 |
| 草稿核对完但无确认权 | 不再要求重复核对，明确等待确认；不能通过AI或修改表单主体来确认 | 3号FB11、4号T03／10，合并稿r2核对状态 |
| 数量不清／新增累计不明／同事实重复 | 可以保留工作，正式量不变；只在有依据时补必要信息，不凭相似度或键不同累加 | 3号FB02／06／07、4号T04／06 |
| 确认后超时、撤权或旧输出晚到 | 原操作可按当前权核结果；不多记、不泄漏、不盖新核对；页面不以通用失败诱导重办 | 3号FB05／09—11、4号T03／05／10／15 |
| 结果已成立但任务／通知没完成 | 同一结果可引用，三个状态分别显示；不为了刷新看板让员工再报一遍 | 3号FB01／12、4号T08／11／12／14 |

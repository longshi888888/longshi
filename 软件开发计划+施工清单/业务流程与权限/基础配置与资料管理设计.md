## 2. 人工操作与输入输出

| 页面／动作 | 人工输入与前提 | 可查输出及边界 |
| --- | --- | --- |
| P15查建物料 | 当前维护权、可靠编码／名称、单位、规格用途、备注及已有来源；缺项可留待补 | 有稳定身份的候选／有效条目及本次版本；同名提示不自动合并，不顺便建立库存或报价算法 |
| P15维护单位 | 单位名称／标识、适用量纲与用途；换算另需明确双方单位、条件和适用依据 | 可选单位及明确待核项；件、公斤、尺寸单位不凭名称互换，未核系数不生成换算结果 |
| P15客户字典 | 级别、区域、行业、渠道、跟进目的、意向类别等各自含义、名称／关系及适用范围 | 分类型列表、可靠引用及历史；客户级别不与其他A/B类别强并，区域近似写法不自动合并 |
| P15业务字典／配置 | 送货／付款方式、服务类别及公海／审批配置的本次内容、操作者资格、所见版本与依据 | 配置草稿／适用版本或具体待核原因；保存付款方式不立账、保存审批项不批准业务，阈值／路由不猜 |
| P18个人显示 | 本人获准的字号／显示偏好 | 本人可读性变化；不增减对象、成本、原件或确认权限，不统一新增审批 |
| P18修改密码／退出 | 可信当前会话、适用身份核验；改密和退出分别办理 | 成功／失败／会话状态可解释；密码不作普通配置导出或明文日志，其他设备会话处置按明确策略检查 |
| P18菜单／表单／模块／系统／应用 | 限定管理范围、本次配置差异与版本；应用扩展另核来源、许可及维护影响 | 可审阅的配置／扩展候选；隐藏菜单不是授权控制，界面字段不能绕过正式业务规则；无安装或任意脚本执行授权 |

| P19找回／人工整理 | 编号、名称、标签、获准可读正文或明确对象／版本；人工补记注明来源性质 | 获准匹配与依据版本，未命中／未处理／暂不可用分开；无识别时不承诺扫描图或音视频全文检索 |
| P19改名／移目录／添新版 | 当前动作权、所见资料／清单版本及本次变更 | 新关系／清单或新字节版本、原引用保留；改名不换字节身份，“最近上传”不自动成为业务有效版本 |

## 3. 启停、版本和配置生效

启用／停用是候选管理能力：按当前资格、适用范围与所见版本办理，说明对新选择及在办记录的影响；不把停用当永久删除，也不让旧表单盲写新配置。
已被订单／任务／资料引用的条目保留可解释身份、当时含义和必要版本；修改名称、区域层次或分类，不无声重写历史归属、统计或已确认结果。
单位／规则含义变化须能区分旧新依据，不把旧“件”条目直接改义成“公斤”；原数值、单位、用途及当时换算依据一起解释，不套当前默认值重算旧单。
配置保存、适用核准、供新办理使用及历史业务生效分别判断；不强制所有字典都走审批，但需明确本次动作的资格／检查／生效条件，未知则不自动驱动正式结果。
付款条件、公海保护／领取、自动分级、审批路由等缺口集中保留，不填默认天数、金额或公式；配置回退也不自动撤销已经发生的业务。
个人字号与菜单布局可独立保存；权限／业务规则、系统范围变更须按各自资格办理，不能靠换菜单、恢复账号或应用扩展取得旧权或管理权。
菜单／表单／模块／应用先限定实际需要的可配置范围、输入验证、版本及撤回路径；不据几个入口重造全部低代码、插件市场或新增多套服务。

## 4. 文件、目录和提取失败的人工路径

| 情况 | 资料页应显示什么／怎样继续 | 不能误报什么 |
| --- | --- | --- |
| 重名而字节不同／同字节多处引用 | 分别保留资料身份／来源及版本；有权者核可靠引用，同字节也不自动共享业务权 | 不按文件名覆盖，不泄漏其他人是否存有同件，不自动合并订单 |
| 目录选择尚未枚举完 | 清单未完成、已发现逐项状态及不可读项；空目录也作为逻辑清单内容 | 已见数量不当完整总量，不因已传项完成便报整夹100% |
| 一夹部分成功、失败、结果未明 | 逐件列已保存／失败原因／原操作待核；未明先回查，再仅重试核实未完成且当前有权的项 | 不盲重交全夹，不把字节收齐或传输偏移当版本登记完成 |
| 原件已存但提取失败／未支持 | 按权限看原件；可另存人工标题、标签、摘录／复述并注明原件版本和未核含义，稍后按原版本重试 | 不删原件，不称内容为空／已识别；人工补记不伪装OCR原文，不直接改正式业务值 |
| 新版或新核对后旧提取才返回 | 旧输出归原输入版本／尝试；人工修正与当前核对保留，可解释差异 | 不覆盖新版、旧确认或当前业务依据 |
| 原件暂不可读／登记未完成 | 显示受影响版本暂不可用或保存待核，其他获准正常资料仍可办 | 不偷换同名文件，不把来源缺失当没有业务或返回空内容成功 |

原件读取、预览、搜索命中、整件下载、关联和导出各核当前对象／字段／动作权；连存在性不可见时不透露名称、数量或旧链接。能看订单不自动能看成本整件。
上传、保存、提取、人工核对、按类别上报与正式业务确认分别留依据；不统一增加上报按钮或把上传完成当全部动作完成。退出／停号不承诺召回已交付副本。

## 5. 输出、保留与恢复边界

导出前明确本次范围、版本／时点、格式及包含清单、原件、人工标注中的哪些内容；生成、领取和重开核当前权，选定产物与页内结果可对账，不默认Excel或全库打包。
目录导出要列已获准内容和逐件成功／失败／未明，不能将可见清单标题当全部原件可下载；未知覆盖不冒作完整总数，业务引用不变成永久免鉴权直链。
删除、作废、清本地缓存、清共享原件及备份保留是不同决定；保留／清理规则未定不设自动永久删除，已有有效引用不能因另一份删除而损坏。
恢复候选集合包含一致业务库、被引用的原件版本／目录清单、人工修正、必要配置／规则版本及受控恢复凭据；密码／密钥不作普通用户导出，数据库与文件时间相近不证明引用闭合。
先隔离恢复，再核引用／缺件坏件、当前授权、配置适用性和未完操作；旧通知不直接全部重发，确认后才开放相应能力。派生索引可重建，人工修正和原件不能只靠重识别补回。
现有r5证据仅含短连接上传、最小顺序台账与静止SQLite／文件集合限定恢复；曾有整树恢复失败后同快照子树恢复成功。不是本稿产品、生产PG在线跨存储、当前授权或完整灾难恢复通过。
具体产品、公司／云位置、容量、保留期、可承受丢失及恢复时间仍待维护方案，不因工具箱已装便选型；本稿没有新安装、备份／恢复运行或公司资料外送。

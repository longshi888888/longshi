## 给使用者的一句话

找到订单的某条明细，留下“哪部分、哪个工序、依据是什么”；有适用资格和依据时再明确登记结果。**只保存一段说明不会自动变成完工，做完一部分也不会把整单变成完成。** 普通情况不强制另设审批人；是否需要、谁能办以真实制度为准。

## 1. 本段要解决的真实差距

上午新虚构单可普通建明细、补原话、交办／反馈、保资料，但仍主要回答“谁说了什么”。旧S01／S02的逐件结果与新ML行并无可靠实物映射；复制旧结果或给4件自动生成4个实物编号，都不能证明新甲行哪2件已做好。

本段先给一条明确局部范围的首次工序结果设计路径。真实G03谁可办理、G04何为加工完成仍待公司负责者提供依据；本卡没有替其确认。可以继续做明示虚构范围／规则／资格的隔离验证，不能据此放行真实完工。

## 2. 最小例子，哪些知道、哪些不知道

| 项目 | 候选例子／处理 |
| --- | --- |
| 对象 | 上午AM1第一单、甲行（所述需求4件）；乙行需求未知，保持 |
| 范围 | 明确标“合成工作包P01：甲行本次局部2件”；是虚构可辨认范围，不冒称公司批次／实物编号已存在 |
| 工序 | `demo_processing`，页面标“实验加工工序”；不代表报价／收货／付款或整单流程已完 |
| 依据 | 当前有权读的已存原话固定版，加必要的范围／单位说明；附件可选。原话主本不重抄成另一权威记录 |
| 候选结果 | P01的该工序2件，由有对应演示资格的人明确办理；原话保存时间与实际发生时间分开，发生时间未知可留未知 |
| 未知 | 其余2件加工状态、整单累计、乙行和物流／回款仍未知；2/4不能直接推出整单50% |

系统范围ID只保证引用同一登记对象，**不能认证真实范围互不重叠**。若同事又说“另有2件”，没有可靠区分就只能留反馈／待核，不能新建一个名字后自动加成4。按批次汇总前须有覆盖／不重叠依据，不把去重键当物理防重。首次小样仅一个明示范围；多批拆并及覆盖算法留后续。

## 3. 操作与数据怎样交接

1. 从可靠当前订单／明细发起，带出order-ID、line-ID、所见明细集合版；不能手敲任意ML号或按行位置拼接。
2. 复用“明细下补一句”保存原话与人工引用。此步只写原话／引用／本动作回执，没有加工结果。已有原话可选固定版；含糊、只有聊天标题或无法识别范围时仍可保普通跟进。
3. 另行明确本次范围、工序、数量／单位、适用依据和规则。保存依据与办理结果可分两次；若真实规则允许同人一次明办，也可在一个清晰动作和同一事务中办理，**不为了技术分层强制员工重复点击或等待审批**。首个实验拟分两次，以便验证不自动生效；这是验证方法，不是产品制度。
4. 明确办理前，后台核当前账号对该目标的读／办理资格、来源读取及适用性、范围归属、工序／单位、所见版本及原操作身份；不能只凭“有订单读权”或“我上传过附件”放行。
5. 同一事务保存首次结果、结果所指固定依据／规则版本及办理回执；若任一末写失败，全部回滚。没有结果先写、回执后补的半套状态。
6. 结果显示“P01／实验加工工序／已确认2件／依据及办理人时间”，其余未知明示；按当前权限读回。任务回复、原需求、计划、实际发出、其他行保持原义。

**候选交互字段**只用于说明职责：原操作键；order／line／所见set版；basis身份／固定版；scope身份及可解释范围；stage；quantity／unit；适用rule身份／版。服务端核定记录人／时间，不接受客户端自报为可信身份。API路径、DDL、正式角色与生产规则尚未定稿。

现有结果表按`detail_pieces`集合计量，新人工明细仅有行与所述数量，两者不能直接共用旧“2个piece”的接口。下一实现前须择定独立局部范围记录与读取适配，禁止造两个physical piece骗过外键。只保一条首次范围结果的限制是实验边界，不推广为公司每行只准一次完成。

## 4. 首次、重复、补证与更正分开

| 情况 | 本段应如何处理 |
| --- | --- |
| 已成功同键／同内容查回 | 核当前原范围权后返回同一结果，不新写；不要因为携旧所见版就强迫换键 |
| 原键换行／工序／范围／数量／依据 | 核原操作真实范围后明确冲突，不把它当重试，不泄无权对象 |
| 两个新键同时办同一实验范围／工序 | 至多一条首次有效结果；另一次查明已存在或冲突，不生成两份数量 |
| 已有结果又提交新“首次” | 不覆盖旧结果；展示可读旧依据，保本人未提交输入。补证／更正是后续独立动作 |
| 范围无法区分或单位不适用 | 可留普通原话；暂停该结果办理，不默填范围、0或单位换算 |
| 结果未明／资格暂失 | 保原请求；按原账号／对象查原，不换键补写。失读清已读投影，本人稿按原范围保留 |
| 发现原结果错了 | 旧结果及依据保持；不能用DELETE或再写一个负数偷偷抵消。既有更正设计可借鉴，仍须针对新范围重新验证 |

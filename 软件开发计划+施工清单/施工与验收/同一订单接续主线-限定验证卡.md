# 同一张订单：跟进、任务、资料和首次安排

2026-10-29 · revision 1 · proposed，1号。本轮用户“好，下一步”承接同一张单主线，按既有隔离虚构验证方式执行准备；不是正式员工软件或公司制度批准。旧原O订单、progress案例、PD-W/J保原样，不凭名字相似硬配；不新建另一张same_orders冒充统一。

## 员工实际应能做什么

从正常入口新建示例订单，在同一页留一条跟进；明确标题/要求/接收人后下发任务，员工在自己任务入口回复；发起人回到同一订单看到回复和相关资料，再安排本次明确的两件货。已有可靠信息带出，不要求每处重新找单或抄整单。

本段只验证关系和正常接续：任务有回复不算整单完成；资料保存/引用不等上报或批准；安排不等实际发出/签收。实际登记/局部进度、复杂改排及正式统计不是在本段顺带实现。

## 1. 独立虚构输入SO-A

| 输入 | 明确前提 |
| --- | --- |
| 新来源 | `DEMO-SAME-01`为明确合成来源，不是历史资料里某个客户/订单；示例单位件。另有独立`DEMO-SAME-02`仅作跨单反例 |
| 普通新建 | 从原订单接口实际生成新O-ID；示例需求10件、交期及说明由人填写。不能预置最终订单后称UI新建 |
| 跟进与任务 | 普通文字补记引用新O-ID；任务沿现有可靠followup引用，标题/正文/接收人由人明确，打开/存草稿不等下发。新角色“协调演示员/接办演示员”资格为显式夹具 |
| 资料 | 一份本轮合成小txt，字节/hash/大小留证；人工保存/整理、指定版关联同一订单，必要时再引用到对应任务。不是公司原件或批量迁移 |
| 本次安排 | 来源中明示S01/S02两件有据适合本次客户交付，单位件；新安排直接引用真实orders.order_id。演示日期2030-05-08/14:30，演示司机，重量与实际状态未知，不分摊整单重量或算剩余8件 |
| 权限反例 | 协调角色能办本来源相应动作；接办角色能读本人已发布任务/反馈，不自动取得整单/全部资料/交付权。另有只读/空范围及跨来源错误对象反例 |

来源/范围/账号资格是预置，业务新建/补记/草稿/下发/回复/文件与关联/安排需在普通入口分动作留下证据。原数据与原对象字节保护、自己资源正常停、源冻结和每段方法分开。

## 2. 具体要接上的身份

- 订单沿既有`orders.order_id`；跟进沿其已有外键，任务沿保存的跟进引用反查这张单，不由任务标题猜归属。
- 资料沿既有order/task精确目标及固定资料版；能看订单不自动能看文件，存在链接也不授原件权。
- 首次安排新增必要研究表，但`order_id`必须外键到真实orders；范围来源必须与该订单真实source_ref相符，不能传另一单的范围冒认。
- 订单页分别读取任务、资料、安排，单块失败只暂停该块；可独立可靠读取的订单/其他块保持。关联清单只作入口，打开目标仍用其当前资格核权。
- 只给接办人的必要任务内容，不自动复制原跟进全文或扩大到原单。原任务动作/材料字节/原引用不因导航连通而改变含义。

## 3. 验证时必须看见什么

1. **普通整段接续：**新建后保存的O-ID在跟进、任务来源反查、资料引用和安排中一致；回单页的链接能打开精确对象/版本再回原位置。
2. **任务与订单分工：**本人下发/回复/发起人读回成立；不自动关闭任务或改订单数量/实际/有效交期，不把回复当阶段确认。
3. **指定资料版：**实际上传/关联并按当前资格读回同字节；不把同名文件或文件hash当业务关联，不因后来有新版换掉旧引用。
4. **跨单/越权拒绝：**SO-02范围不能排到SO-01订单；接办人不能借已知O-ID看整单或混合资料/安排；只读不能通过新入口写入。
5. **原操作与局部故障：**未明先查原操作；旧成功不重复写，换对象/内容不能借旧键，先核原范围再谈冲突。单块读取失败不把其他已可靠内容清空；切号/失去目标资格另清相应投影。
6. **保护与收尾：**旧业务行/对象保持，新增行和本轮登录会话变化分别解释；自己实验/查看资源分开，不动运行中的R副本。测试条数不算功能数，不把整段一例称完整旧功能迁移/生产验收。

## 4. 本段做完仍保留什么

真实规则、正式进度/实际登记、更多格式/大文件、多接收人/转交/审批、复杂安排/改排、报表、Windows/内外环境、成套恢复与维护承接继续按原完整范围。SO-A连通也不把旧独立实验的结果强迁成同一业务事实，完整36B与原16W及六份受审文件保持。

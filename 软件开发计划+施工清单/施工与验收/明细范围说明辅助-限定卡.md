# 明细范围说明辅助：限定卡

2026-10-31 · revision 2（r1原字节见项目外range-note-prototype-20261031/docs-before-rn2/3.md） · proposed／项目外虚构小样。承接两小时任务中的“来源／范围普通入口”与2号范围入口补查。r1以HR4为先前候选；r2新候选RN2及其303项恢复包另见下方实测，不改旧HR4归档。新根range-note-prototype-20261031独立，不能改活跃只读观察的源码或资源。

目的：员工已在明确明细下补一句时，提供默认折叠的可选写法辅助，帮助讲清“整行、已有哪部分、新的一部分尚未对应、暂时不清楚”。懂得直接补记的人仍可直接写，不新增强制字段／审批／第二次保存。

实现候选：复用现有line-notes的原话主本＋本行人工引用＋回执同事务。辅助只是经用户明确点击，把本人声明文字加入当前textarea，仍由员工检查并点击原保存按钮；不新建scope、票据、结果或结构化可信范围关系，也不由关键词判完成。已有部分要写能找回的记录／标记，仍是本人声明，不能把文字相似当稳定范围身份。

固定例子：甲行所述4件、乙行未知，原P01局部2件保持。整行声明仍不表示4件做好；“上次交接那2件的补充”不新增2件；“上午那批好了”可留未知、不默认P01。辅助不插入scope-ID，不让员工手抄技术编号。

| 验证 | 预期 |
| --- | --- |
| 甲整行、乙整行未知 | 文本显示本人声明及已知所述数量／未知，不自动把未知变0 |
| 已有部分／新部分 | 已知定位说明须人填，保留原文字；不能新增系统可信范围或计量 |
| 当前本行已写文字 | 加入辅助不静默覆盖；切甲乙各保原稿，不将甲文字搬给乙 |
| 失读／切号／未选行／已有待查 | 没有可靠上下文不生成本行辅助，原补记草稿按既有规则保留 |
| 普通保存与重开 | 只有既有followup／line-ref／line-note-op增量；局部scope/basis/result/操作、任务、资料、计划和原件不变 |

本段仅限定原话表达，不解决真实范围建立、不重叠、多批拆并、完成依据或岗位权。先模型／源码核，再普通新副本两例；失败留版本，未跑不写已实现。若结束时间到，正常收好本人资源，下一再做同版整合而不拿HR4包证明辅助已恢复。

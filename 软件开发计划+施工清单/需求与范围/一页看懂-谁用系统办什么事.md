# 一页看懂：谁用系统，办什么事

2026-10-29 · 第4版（第3版原字节留项目外task-bridge-docs-before；补运营交接、物流条件和实际任务桥）。依据主管流程图、部门资料和旧软件功能整理。**下表是系统要服务的工作，不代表功能都已完成，也不是已经核定的岗位或权限表。**

**我们要做的是：让一件生意从客户提出需求，到订单交付、后续对账收款，相关人员都能找到该找的信息、知道自己要办什么，老板能看清关键情况。** 当前重点先服务正在进行的订单。

| 谁会用 | 什么时候需要 | 系统准备帮他做什么 |
| --- | --- | --- |
| 运营获客人员 | 网上找到客源／收到询盘，要交给业务接手 | 留来源和需求、查可能重复、明确分配，查谁接了、是否反馈及后来是否转单 |
| 业务人员 | 接到线索、客户问价给图或提出新要求 | 接手跟进、补必要信息，找以前的沟通、报价及重要变化；多次询盘不当一个订单 |
| 报价及审核人员 | 要做报价、改价或核对条件 | 看清材料、规格、加工要求，做报价并办理适用审核 |
| 下单员、PMC、跟单 | 客户确认后要下单、排期，或追问进展 | 查订单要求、交期、相关责任和进展；核未出货与遗漏，按日期／车次安排出货并跟进异常 |
| 生产、品质相关人员 | 有关键进展，或出现加工、质量问题 | 补必要反馈、保留依据，跟踪问题处理；具体确认规则另核 |
| 送货、售后跟单 | 安排发货、跟物流、确认收货或处理客户问题 | 找送货资料，回传预计／到站／到客户及实际交接；按有据条件区分待送、通知自提与实际提走 |
| 对账、财务及业务收款人员 | 对账、整理票据和收款明细、跟回款 | 找对应单据和明细，看待跟进事项；实际到账及核销分别按规则办理 |
| 老板、主管 | 想知道哪些事情卡住、谁在跟、结果怎样 | 查获准的订单、任务、异常和汇总，安排事情、看反馈及目标与实际 |

**有人回复了，不等于事情已办完；需要审批的事项按适用规则办理，不要求所有事都审批。**

这些工作围绕同一条主线：

**运营线索／客户询盘 → 业务接手 → 报价与确认 → 下单／排期 → 进展与异常 → 排货／物流／实际交接 → 对账／收款。**

报价前的线索不一定成交；计划发货不代表已经发出，物流“已到”不一定是客户已签收。有些交付涉及先跟回前款，要按该次有据条件处理，不能一律套成先款后货。

**任务和资料贯穿其中：**需要别人处理就派任务；值得保留的文字、图纸或说明放到相应事情下。任务也能独立存在，不要求每件事都绑订单。行政申请、设备维修、审厂、拜访与工作汇报、组织配置等仍在完整规划中，不因当前优先订单而删掉。

**现在做到哪里？** 已有虚构小样能演示部分订单登记与文字跟进、从已存跟进准备任务草稿后明确下发及本人反馈、文字／小txt／小PNG/JPG/PDF保管与指定引用版查看。其他板块主要还是规划，完整业务规则、报表和正式员工软件尚未完成。

**接下来怎么判断做得对不对？** 助手按已有资料检查功能覆盖与操作关系；真正涉及岗位规则的缺口，留给对应负责人核实。你先看公司要解决的工作和整体方向，**不用代替各岗位逐页验收按钮、字段和专业流程。**

**你新提供的PMC工作也包含：未出货核对、每日出货排单、车次／时间／司机安排、业务补漏和实际发出跟进。** 这是完整基础功能的明确内容，当前演示尚未做；具体首批深度继续收拢。送加工与客户发货分开，排进车次不等于实际已发。详见[去标识需求补证](../../AI调研/产品经理调研/2026-10-29-PMC未出货跟进与每日出货排单-需求补证.md)。

基础办理、查找和固定规则统计应独立工作；AI后续辅助提取、查询、总结，不代替有权人员作业务决定。

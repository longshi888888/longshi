### 首节点的具体取舍：少填一次，一张清单看清下一步

以下为助手提出的细则，设计顺序已选不等于这些细则已获公司批准。复用[既有十二例反馈走查](../../AI调研/产品经理调研/2026-10-27-员工反馈正常异常纸面走查.md)及[订单操作与状态](../../AI调研/产品经理调研/2026-10-27-在途订单操作与状态候选.md)，不再另造一套案例编号。

员工从可靠订单或任务进入时，系统带出已有对象／范围；最少只补“这次发生什么”的短记或获准资料。数量仅在本次需要时补，未知发生时间保留未知，提交人／提交时间由系统记录。没有可靠关联也可先独立保存，不强制重抄客户／单号、附图或补历史。

| 本次目的 | 一次操作应办到什么 | 还不能据此改变什么 |
| --- | --- | --- |
| 先记下内容／选取资料 | 保存已知内容，查回逐件状态及待核处；上报触发按资料类别另定 | 不统一上传即上报，也不强制每次再点一个上报按钮 |
| 记实际进展 | 有可靠范围、所需口径和当前动作权时，可同一次明确核对并确认；否则保留反馈待核，转适用有权者 | 不固定每次主管二次审批；不把局部加工、任务验收或检验合格互相替代 |
| 提出新要求或录错更正 | 同页看当前依据与待处理变化，指出影响范围；按适用资格／规则办理后才改有效结果 | 客户改期／改规格不直接覆盖当前要求；真实返工另记，不当纠错或直接加减有效量 |
| 回复交办事项 | 直接在已发布原事项反馈，可引用同一业务结果；草稿不自动发布，转交未生效不先换当前责任；适用验收按规则办理 | “已联系，等回复”不生成加工进度；一个人收到不代表所有人已读，反馈不等验收 |

老板／主管候选首表为 **《在途订单跟进清单》：一行一张稳定订单**，先用于找单、识别缺口和下一步，明细／工序在P05展开。一单有多条范围结果不能增成多张订单；各阶段和不同单位不相加，不用最新一条反馈代表全单。独立事项回P08，独立资料回P19，不为凑此表制造订单。

| 候选显示组 | 展示内容及来源 |
| --- | --- |
| 找哪张单 | 可识别订单／客户、已明确的跟进负责人；源自现有登记，未落实责任留待安排 |
| 现在知道什么 | 获准范围内的有效结果摘要＋具体明细／阶段范围；待核反馈和需求变更分别显示，全单覆盖不足明示 |
| 时间与风险 | 当前有效适用交期、反馈实际发生时间及已知精度、登记／确认时间可展开；未获更新不当未开工，阈值未定不自动标超时 |
| 接下来找谁 | 下一步动作／负责人及关联事项情况；任务期限与订单交期分开，不因任务逾期就给订单判延误 |
| 从哪里核对 | 当前获准的依据／版本入口；原件整件读取另核，连来源存在也无权时不暴露名称／数量／存在 |

表头保留查询时点、当前可见范围、筛选排序及覆盖说明；清单数量只指同一条件下获准的订单数，不向无权者提示隐藏数量。先建议提供页面及其一种可检查的输出，具体格式／字段待审，不默认Excel或PDF。输出标明当前页还是全匹配；生成和领取均核当前权，数据变化时说明时点或重新生成，不为“保持一致”保留已撤权内容。

可直接审阅[首节点固定例子及未来检查](../施工与验收/首批代表场景与验证卡.md)第0节：两单、一张独立任务、一份独立资料，包含4改3、改期待定、任务逾期、缺更新、原件受限和回执未明。只做纸面输入—结果核对，产品仍待实现和运行。下一段按该例子收拢本节点任务片段及业务／维护条件，不继续扩报表或要求同事填问卷。

此前r5的原候选是：建议第一批让获准员工能完成三种工作：**新需求到报价和订单、已有订单接续与进展纠正、无订单的日常交办及资料保管**。都能人工办理、普通查回和做已定汇总／输出，AI后续增强；不会只交一个客户列表或上传页。

员工尽量只录一次关键变化，关联处按权引用；不搬每条聊天、不补造旧历史。报价按客户要求，公司优先净尺寸；重量如何取小数用户已回复“待核验”，保留缺口。草稿能保留已知和待核，正式办理不能拿猜测补齐。

维护方用户已答**尚未确定**，不能默认由实习生或AI接手。按1名有经验的主要全时开发者、兼职测试／运维和业务短核可用的假设，合成任务演示先按**1—2工作周**考虑；**原三片段一起交付的对照预算为10—18全栈人周，新推荐在途节点为6—12累计人周**。均低置信、非测得工期、从今天倒数或完整36组交期，二者不相加。假设／分解／额外投入及维护职责见[首批投入量级与维护安排](../决策与变更/2026-10-27-首批投入量级与维护安排.md)。四个AI窗口不折算四名工程师。

| --- | --- |
| 首批做什么，其他旧功能何时补 | 本稿第2／3／5节；9个配套功能包及完整36组去向仍是候选，范围未批准 |

### 本轮新增业务答复及边界

问：已有按净尺寸和加余量计重的板料模板，实际按什么条件选择？用户先答“客户要求，不同客户有不同的报价方式”，随后补“公司是优先选择 净尺寸计算”。来源为1号用户本轮直接答复，未声称本轮独立访谈报价负责人或核完公司全部执行。

因此，客户要求决定报价方式，净尺寸为公司优先方式，其他客户方式仍须保留。建议优先细化净尺寸板料代表场景，并在每笔报价留本次实际方式/条件/版本；客户偏好带出是设计建议，不能直接回写历史或在缺条件时生成正式价。密度/单位、余量数值、费用/税费和精度/舍入等没有因此核实。

## 1. 原三场景整体候选：保留供比较

让获准的实际使用者能从客户需求开始登记报价、办理适用审核和客户确认、建立订单，随后留关键进展/异常、安排任务，并通过普通页面查回结果和基础汇总。

同时允许接续已有进行中的订单：人工补建可靠的当前资料和已知基线，不要求每张旧单重新报价或补完整聊天历史。缺历史、数量或映射时明确待核，不能当新单从0累计，也不能编造客户接受/审核记录。

这个试用节点横跨[批次表](../施工与验收/基础版分批开发与验收表.md)K1—K4的必要片段和相应固定统计/输出；K编号表示施工依赖，不直接等于一次上线范围。完成本节点不代表整张订单已履约或全部旧功能已替代。

## 6. 三种使用场景：检查人怎样完成一件事

以下为虚构纸面场景和未来期望，不是本机产品运行或公司制度验证。以当前有权、基础服务可用为前提；核对者与业务确认者可由同一合格人员一次办理，不固定增加多轮审批。

### S-A 新需求到订单建立并可跟进

示例客户甲要示例物料2件。此例假定该样本的规格用途、按件单价500.00及所需审核/客户接受条件已另行给定，不能推广为公司通用计价规则。

1. 员工人工登记客户/关键需求及已有图纸或说明，保存后从普通入口找回。缺非必需资料不强制上传整段聊天，正式办理必需的缺项明确提示。
2. 相应人员录入报价内容和适用条件，按这个明确样本得到金额1,000.00；内部成本及对客内容按实际权分开，原版本可回看。
3. 有权者办理适用审核；对客报价、客户接受和内部传单/下单各留实际依据。内部审核通过不直接等客户已接受；普通任务不代正式下单。
4. 按已核关系建立订单并引用适用内容，同一办理的重复点击不能再多造一笔。业务员、具体负责者及当前安排可查。
5. 岗位只留一次本次加工反馈1件或异常，有权者按实际规则处理；订单、原任务及管理视图引用相应同一记录，不再让员工抄一份“任务完成数”和老板汇报。管理者无需等AI总结；被引用的待核记录不自动变有效进度。

**这段完成的结果：** 客户需求、适用报价/确认、订单、安排和当前反馈能按权查回，已成立与待处理内容分清。订单登记金额不叫回款/利润，加工反馈也不当整单完成；本段不冒称已经履约。

若客户后来把2件改成3件，先保留新要求和影响范围；未按适用条件生效前，原有效数量、报价和已做历史不被悄悄覆盖。需要重价/再确认/调整安排的部分分别办理，不统一硬加一轮老板审批。

### S-B 已有进行中订单接续，历史不齐仍可留可靠信息

实际负责者提供可辨识的当前订单/客户、具体明细和已知要求，但此前加工累计、历史报价或某些记录不全。

1. 员工据可靠材料接续对象和当前已知要求，保留来源/时间和待补处；关联仍不能可靠确认时，先保留独立资料或待核，不猜一张相似单。
2. 已知本次反馈1件可以留存并查回；没有可靠基线不能因此显示“累计完成1件”“还剩若干件”或整体百分比。
3. 跟单/适用岗位补齐关键范围或当前安排，PMC统筹的记录按有权范围查看；不为接续而逼员工重填全部历史聊天或重走原报价。
4. 管理者看到“本次有反馈、累计待核、谁在补”，可安排下一步。规则确需某个未齐依据的正式结果仍待核，其他齐备的独立工作可继续。

**这段完成的结果：** 在途资料与当前事项有可用入口，已知/未知及责任可辨。补建是本次登记动作，不能直接当新成交或重计历史金额；相应统计的业务时间/状态规则仍须先明确。登记工作量若需要统计可另明示，不能混称经营成交。

### S-C 独立任务交办，不强制造订单或附件

主管安排示例员工联系客户了解交期，暂没有可靠订单关联，也没有附件。

1. 有权发起者直接写清要求、任务负责人/通知接收范围及适用期限，保存并查原事项；不强制先填订单或上传图片。
2. 员工反馈“已联系，等待对方答复”，这条反馈在原事项可查；若以后有可靠订单再按权关联同一记录，不复制一份来凑看板。
3. 相应人员继续跟进或按适用标准验收；任务反馈、通知送达/已读、审批、客户接受及执行完成分别按实际依据显示。
4. 保存/发送结果未明时，先查本次原事项，不一律重发再创建。没有可靠阅读依据，就不显示所有人已读。

**这段完成的结果：** 能交办、反馈、查下一步并在需要时回业务；无AI、无附件、无订单的普通齐备事项照样有人工路径。

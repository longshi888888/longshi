# 首版在途订单范围候选

2026-10-27；revision 2；supersedes r1：接操作/验收纸面收敛和对应来源，范围仍待审；r1保全项目外。1号整理。方向来自用户本轮明确要求：服务未完成/进行中订单，完成订单可留作历史分析。以下操作范围为proposed，仍需审阅；不是正式开发批准或已核公司制度。

## 工作中心围绕订单当前情况组织

进入系统先找到有权限查看的进行中订单，了解：客户需要什么、最近发生什么、目前有哪些已确认结果、哪里异常/缺更新、谁在处理什么。已完成订单另有历史入口，保留来源、变更和分析所需的时间口径。

“进行中”“待核对”“需处理”“历史”可以是工作视图，不能把文件处理状态、订单业务状态和任务状态混成同一个进度条。当前没有资料不等于未开工，某加工范围完成也不等于整单完成。

## 本次要细化的功能边界

| 功能 | 候选行为及边界 |
| --- | --- |
| 订单建立与查找 | 本系统可登记当前订单并建立稳定内部身份；实际建单权限和最少字段待按依据落定。也可先留独立资料/事项，后续有依据再关联；不能把询价或相似截图直接变成已确认订单 |
| 订单详情 | 关联客户需求、明细/加工范围、关键变更、过程反馈、有效结果、原资料及事项；按当前权限展示，不能用文件名或客户同名确认唯一关联 |
| 员工关键反馈 | 从已关联订单/任务进入时带出范围，选关键文字/截图/音视频或简短补记；可直接填写已知变化，不强制每条聊天登记或每次调用AI |
| 系统整理与人工核对 | 提取结果作有出处的草稿；员工只核需要变化和不确定的部分。允许先存资料再补关联，识别失败不阻止保管或人工补记 |
| 过程与异常 | 展示获准范围内的已确认结果、更新时间、异常和缺更新；明细、工序、各类批次分别表达，不由AI猜全单完成比例 |
| 派任务、通知、讨论及适用审批 | 可围绕订单，也可独立发起；反馈、审批、实际执行、验收和送达分别处理。尽量引用同一结果，避免员工重复填进度和汇报 |
| 老板/主管查看 | 按权限看当前订单及待办、异常、时间和依据；先由业务服务取可信数据，AI帮助找资料、总结和展示，不直接改正式内容 |
| 完成后留档与分析 | 何时允许标已完、谁确认和如何重开仍需明确；记录当前有效结果和历史。已完记录可分析，但不可混入“正在进行”的分母；发生、更正、录入和确认时间区别保留 |
| 搜索和资料维护 | 编号/关键词/语义候选共同辅助找当前或历史资料；结果带权限与来源。检索、归档、导出都不能绕过授权 |

这是一条可操作主线，整体需求及18个调查域仍保留。真实成本/财务口径、全部工序制度、完整部署等按既有覆盖表继续调查，不因聚焦而默认删除，也不自动全部纳入第一批实现。

## 由助手解决的下一层细节

1. 正常/异常操作：逐步写出员工看到什么、最少做什么、系统保存什么、什么情况下允许推进；覆盖识别不清、无可靠关联、重复、晚到、冲突、更正、返工、无权及网络结果未明。
2. 技术与验收：为每步对应现有模块、候选组件、输入输出和正确/错误行为；引用既有实测时带限制。缺证据的列成具体风险，不能把纸面走通当运行通过。
3. 规则仍不明确时：优先从资料查明；设计可安全选择的部分给出建议，无法代公司决定的保留待核并说明阻止哪一步，不能为了“解决问题”编造岗位授权或完成口径。

本轮由原2号补订单操作/状态候选，原3号补员工反馈正常异常走查，原4号补技术职责/验收对应；1号审核冲突、整合范围和向用户汇报。连接状态以[本轮协作记录](../../AI调研/协作管理/2026-10-27-四窗口接入与分工.md)实际回执为准。

基础图纸：[系统设计总图r4](../技术与部署方案/系统设计总图.md)。不新增依赖、不跑新组件、不接正式数据、不推送；用户审阅相关范围和门槛后再进入正式业务开发。

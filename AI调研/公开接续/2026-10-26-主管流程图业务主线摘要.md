# 主管流程图：业务主线及对规划的影响

日期：2026-10-26。整理：1号。revision：1。supersedes：无。

来源：用户本轮提供流程图，并说明刚从主管取得。1号直接查看全图，原件及人工逐字记录保留在本机私有资料区。本文为去姓名、电话和原件标识的研究摘要，不是原图复本；未取得文件制订日期、版本或岗位执行验证。图载流程可作为宏观业务底图，不等于已批准的软件状态机、系统权限或ERP能力。

## 一条主线、十二个交接点

| 图中步骤 | 岗位／载体及图载职责 | 系统调研应保留的边界 |
| --- | --- | --- |
| 01 接收询盘 | 网络部接收；确认产品、材质、规格、数量、交期、图纸 | 询盘不等于客户已确认订单 |
| 02 分类报价 | 报价群分钢材、外协、模胚三类，资料完整后提交审核 | 这是报价分流，不是全系统所有资料的分类全集 |
| 03 报价审核 | 工程经理审核内容、成本和报价条件 | 审核、报价发送与客户接受分别记录 |
| 04 大额报价？ | 条件分支：大额先与老板沟通确认，确认后方可对外报价 | 非每笔都需老板审批；大额标准和具体路由未定 |
| 05 客户确认订单 | 业务核对产品、数量、价格、交期、收货信息、付款条件 | 与内部传单、正式下单分开 |
| 06 传单群下单通知 | 对应业务员发订单及报价依据，注明交期、特殊要求 | 群通知是交接，不证明下单已执行或生产已开始 |
| 07 下单 | 下单员向供应商及公司内部下单，与PMC沟通交期 | 内部／供应商下单不自动等于一张ERP表或同一编号 |
| 08 交期与出货 | PMC统筹交期、进度、出货，反馈异常并协调 | 进度调查应纳入PMC；统筹不等于包办每个节点录入 |
| 09 送货及物流 | 售后跟单制作送货单、跟物流、联系客户并确认收货 | 出货、物流、客户收货／签收分别成立 |
| 10 对账及整理账单 | 资材与客户对账、对接开票，发票群交接后由业务发送客户 | 对账、开票、发票发送不同；图未完整说明开票人的岗位身份 |
| 11 整理收款明细 | 会计仅整理明细给业务同事，用于跟进收款 | 不据此授予或否定银行入账、财务账修改和核销审批权 |
| 12 按明细收款 | 对应业务员跟回款、核销到账金额、跟逾期；图载业务部主管 | 跟进、实际到账、核销及监督含义仍需在相关设计定稿前明确 |

原图上排01到06，随后07到12由右向左。04是条件分支；图中03“通过后报价”与04的细节衔接未画清，不能自行确定老板与工程审核的完整先后路由。

## 对当前方案的四处修正

1. **主流程和大段职责不再从零提问。** 询盘—分类报价—审核—客户确认—内部传递—下单—排期／进度／出货—送货及收货—对账开票—明细收款已有来源。后续只问真正影响当前设计的缺口。
2. **进度责任加入PMC。** 先前跟单／生产／微信群线索保留；新文件补出统筹岗位。具体节点由谁确认、混合分工怎样减负、何时更新仍未被本图回答。
3. **审批有明确场景，不设全单统一审批。** 报价审核和大额确认是图载条件；其他资料上报、任务验收和进度确认不因此统一交老板批准。
4. **签收、发票、收款交接需要关联。** 可以纳入后续记录关系图，但不代表首版要重写ERP、银行入账、开票或全套财务。首版范围仍待审。

## 哪些问题仍影响定稿

| 仍缺什么 | 何时必须弄清 |
| --- | --- |
| 订单／明细／加工及各类批次如何对应 | 关联与数据模型定稿前；本图没有稳定键，不能据此关闭2号断点 |
| 加工、检验、部分完成及异常怎样确认 | 节点和确认规则定稿前；图未展开这些细节，不等于公司没有检验或仓储 |
| 大额标准、退回改价与再审核 | 相应报价审批规则定稿前；当前不用金额猜测或硬编码 |
| 查看、确认、更正、成本和附件的授权 | 相关权限设计定稿及开放真实数据前；岗位名称不是授权策略 |
| 实际更新频率与操作负担 | 承诺“实时”及现场试用前；画出PMC不等于测出时效 |

内部／外部加工、检验、仓储、拆单／取消、分批收货、退货返工、预付款／分次收款等没有展开，不擅自填成“没有”或“必须按顺序”。经营统计口径也没有因有流程图而自动确定。

# 网络与行政资料对流程和系统的补充

日期：2026-10-26。整理：3号。revision：1。supersedes：无。

依据用户授权的新部门资料，结合[主管业务主线摘要](2026-10-26-主管流程图业务主线摘要.md)与既有研究。这是去标识研究摘要；原件、逐文件定位和提取记录留在授权本机私有区域，不含个人、证件、薪资、客户联系方式、账号、真实业务编号、金额、原件路径或指纹。文档要求不等于现行执行、已批准规格或系统实现。

## 1. 新资料补清了什么

| 主题 | 有来源的文件观察 | 对系统候选的影响 |
| --- | --- | --- |
| 网络到业务的交接 | 有来源渠道、运营归属、接收业务、当前跟进业务、报价、成交及回访等不同字段 | 来源归属与当前跟进分开，改派不抹历史；询盘、报价、客户接受和正式下单分别记录 |
| PMC与加工反馈 | 岗位文本要求明确日任务顺序、交接班、自检和异常上报；工单标注后转待检区 | 加强主管主线的PMC统筹依据；加工完成、自检、品质合格与出货分开，仍需核确认权及覆盖范围 |
| 对单线索 | 部分文本要求材料上保留客户/材料序号及规格等标记 | 可用作候选关联依据；没有证明稳定明细键、实际执行或跨表映射，不因组合相似自动对单 |
| 行政事项 | 外出、礼品、预支、维修、报销出现不同申请、审批、审核、执行和领取要素 | 按事项类别研究路由；模板签名位不等于软件授权，也不成为全部资料统一审批制度 |
| 设备与培训 | 有设备履历、点检、异常报告、培训及考核条款 | 设备事件与订单事件分开；有材料/通知不等于检查完成、培训通过或可作人员评价 |

网络资料的获客渠道分类与主管主线的三类报价分流不同。费用报销中会计核凭证与主管图客户收款明细的职责属于不同业务域，不据此判定图文矛盾或授予全局财务权限。当前没有把薪资、支付、设备控制或开票纳入已批准首版。

## 2. 发现的具体风险

- 网络汇总表存在已保存的除零错误；一些公式把未知/无分母结果表示为零。询盘、线索、转化、金额以及日/周/月等统计不能直接复制到老板看板。
- 观察到“当天线索”标签与公式条件/求和列关系待核，以及“转化成交时间”在某公式中取询盘日期的情况。要分清获客期归因与实际成交期，不能由AI自行纠正或以缓存值评价员工。没有运行Excel重算或整本公式审计。
- 设备规范中有标题与正文设备名称混用、质量文本适用内容待核等线索。保留来源、适用范围和版本，不静默合并成一份所谓统一正确规范；不据此下达设备操作或人员纪律结论。
- 检验模板分订单量、抽检量、实测与结论。空表不等于已检，抽检量不等于合格总量；同名或版式相近文件也不自动等于同版本。
- 保密和个人资料需要独立受控处理。可查看进度不等于能看整件身份/合同等资料；进入AI前就应按当前授权限制字段和片段。

## 3. 对主管十二步的补强与缺口

| 业务段 | 本次增量 | 仍不能从资料推定 |
| --- | --- | --- |
| 询盘、报价前段 | 网络来源及业务接收/跟进更具体 | 唯一线索身份、改派规则、正式交易条件或报价审核/大额路由 |
| 客户确认、传单、下单 | 报价/成交/日期是不同字段 | 成交字段不替代完整订单确认；通知不等于接收、执行或开工 |
| PMC与过程进度 | 日任务、交班、自检、材料/工单标记及待检区 | 关联键、实际批次、节点确认/更正权、数量口径和更新频率 |
| 送货、签收、财务交接 | 更清楚要区分加工、品质和后续交付 | 本专题没有新增送货到签收/到账闭环，报销材料也不证明客户回款或银行权限 |

这些观察延续[关键反馈到可信进度的边界研究](../技术调研/2026-10-26-关键反馈到订单进度的可信链路补查.md)：AI整理来源和字段候选，人工按依据核对，正式生效由当前授权与业务规则控制；任务反馈和阶段结果可引用同一事实，验收仍需单独成立。

## 4. 实际读取程度

限定范围共36文件：网络1份工作簿，行政31份DOCX、2份DOC、1份RTF、1份PDF；没有扩大到其他部门或行政表格。本轮先复用有限旧哈希对照，本范围未命中不代表全是新资料。

- 31份DOCX做文本部件逐段提取，保留段/表格定位。普通流程按段核读；敏感薪酬、身份、住宿及借款四份仅结构审视，不逐条分析个人/金额/责任内容。Word版面渲染缺少现有运行组件，未完成页码、图片及形状连线核对。
- 工作簿8页签均做全量稀疏单元提取，人工核结构、字段和关键公式，抽看一个表头区域预览；未人工逐格审计或运行原生Excel重算。预览有组标题重叠，不能作原生排版保真证明。
- PDF4页全文提取，其中一页做视觉核对；其余页未作视觉复核。
- 3份旧格式文件正文未读。文件签名显示为复合二进制容器，其中一份虽以RTF命名也不能当纯文本读取；没有为了补齐覆盖率而安装依赖或猜正文。
- 36个原件在清单、读取前后及交付前的内容指纹一致。此检查只说明读取未改内容，不证明业务事实、文件有效性或模型正确率。

逐文件覆盖与具体疑点定位保存在私有报告，公开摘要不能替代原件复核。没有模型、权限、性能、业务接口或完整订单实验，没有正式开发、生产访问、对外发布或推送。文档交付不等于全部细节已证实。

后续在既有研究范围内继续形成候选图纸，优先复用已有记录减少重填。关联、完成定义、权限及统计口径在对应设计定稿前仍需依据，不恢复整套问卷；关键缺口由协调者结合资料择机单点核实。遇不熟悉功能先复用并核查同类开源实现，本轮未新增或批准技术选型。

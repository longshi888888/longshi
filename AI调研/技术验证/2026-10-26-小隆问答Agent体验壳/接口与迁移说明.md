# 问答工具接口与迁移边界

2026-10-26，revision 1，proposed／技术体验。没有正式企业接口访问。

## 请求与数据流

`POST ask {question, mode: business|chat}`返回任务id；`GET job/<id>`返回阶段与结果。阶段为queued、routing/thinking、querying、checking、done/error，来自服务真实处理步骤，桌面角色订阅同一状态，不用假进度条。`GET history`、`POST clear`管理本机会话；`GET source`只返回固定合成JSON及哈希。`GET status`只回传是否有密钥，不回传密钥本身。

业务模式最多选择一个当前支持工具：

| 工具 | 参数 | 结果与缺失 |
| --- | --- | --- |
| delivery_query | delivery_no；未指定则空字符串 | 按明确单号精确筛选；不存在时missing，不退回全量记录 |
| reconciliation_query | 无 | Decimal试算、调整及口径说明，不认定批准／付款 |
| payment_evidence | 无 | 当前无凭证，明确未知，不认定已付或未付 |
| system_scope | 无 | 说明本次数据覆盖／接入状态 |
| cannot_answer | reason | 规则／数据不足，返回missing |

结果统一为`title/body/kind/synthetic/rows/columns/metrics/sources/engine/tool`。来源含数据集版本、相对文件名、字段位置和SHA256。金额由Provider的确定性规则计算，模型生成的业务描述不作为最后结果显示。陪聊结果单独标注，不作为业务证据。

## 正式接入前需要补齐

1. Provider获取业务服务提供的授权身份、租户、范围及查询口径；身份不得来自模型自由填写。每次查询由业务服务复核权限，避免只依靠前端隐藏。
2. 查询应包含业务更新时间、状态版本、有效性及来源定位；本次演示文件哈希不能代替未来业务版本。
3. 候选工具只覆盖有限演示问题，不覆盖完整业务需求。结合实际老板问法再扩展工具，调查异常、汇总口径、时效和权限；不开放任意SQL或生产写入。
4. 公司系统可复用Agent与结果DTO，保留独立Provider测试；把本机随机会话认证换成企业认证、撤权、审计、限流和错误处理。模型API密钥改由企业服务保管，不能移到网页前端。
5. 角色仅订阅任务状态、展示入口；不能因角色可爱／会说话就证明结果正确。真实数据与真实模型路由仍需分别验收。

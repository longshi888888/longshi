## 对系统规划有什么用

现成授权库可以承担明确的“谁能对哪个对象做什么”判断；业务服务仍要在给AI资料、发布结果及回看引用时使用当前权限。片段可读不等于整件可下载，来源被撤权也不自动撤掉另有许可的正式业务记录。

最重要的反例是：**格式合法、引用存在、有权限，也可能答错。** 固定来源写“加工2件、检验待核”，人为构造的回答写“6件、检验通过”，仍通过本轮结构/引用检查。这是已暴露而未解决的语义缺口。正式数量和状态应由业务服务取有效记录、执行已确认规则并校验展示值；自由文字解释的语义支撑还须另验，不能把结构通过当作事实确认。

八类主场景的具体边界如下。

| 场景 | 实际发生了什么 |
| --- | --- |
| 跨员工读取 | 员工A选另一员工来源，模型捕获器调用0次；该引用回看和发布被拒绝 |
| 同文件不同片段 | 同一文件含可读摘要与老板专用成本；捕获器只收到摘要，成本不能借文件容器被送入，也不能作为回答引用 |
| 发送前撤权 | 原本选中的两个片段在发送前均撤权；重核后上下文为空，调用0次。已撤片段不能从旧结果继续发布；其他获准来源和正式记录没有被误判为一律不可读 |
| 发送后撤权 | 一个来源先发送，再撤权；之后发布、旧回答复用和回看被拒绝，但捕获器保留的先前文本仍在，无法借撤权声称召回 |
| 伪造/错用引用 | 不存在的ID、无权成本ID，以及有权限却未进入本次上下文的ID均被拒绝；存在且实际进入上下文的摘要作为正对照 |
| 旧版当当前 | 旧版可以有读取许可，但不能标为当前依据；显式历史模式允许查看并保留历史标签 |
| 越权字段和动作 | 伪造actor、策略/来源可信元数据及确认/下载动作被严格结构或授权检查拒绝；请求合法与动作获准分别观察，合成快照未改 |
| 有引用但语义错误 | “2件、检验待核”的来源被用于“6件、检验通过”，结构/引用门槛允许，系统未检查语义成立。不得将其标正式事实 |

内部诊断原本区分unknown_source、policy_denied、not_in_actual_context，原始辅助函数还保留完整夹具元数据。这不是员工可直接获得的响应。独立补充的客户端投影把拒绝统一为`status=unavailable,data=null`，仅向允许的来源/记录输出预设字段；正式记录仍可读时，不随记录返回已撤来源正文、证据列表或权限名单。这只是本地数据形状检查，不是全出口无泄漏结论。

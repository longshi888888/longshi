## 3. EXP-01 本轮实际结果

2026-10-24补充：EXP-10的候选原理、Office职责拆分、社区失败/修复及样本检查要求见[Office与表格组件比较及案例核查](../技术调研/2026-10-24-Office与表格组件比较及案例核查.md)。这次外部研究不改变EXP-10“未执行”的状态。

记录文件：[旧表单OCR核对记录.json（公开摘要）](../公开接续/公司业务资料研究概览.md)。

- 输入：S038、S039、S068、S069；使用已提取的三倍图OCR词框，原件未改动。
- 参考：AI视觉转录的33个可见标签及星号；还没有第二名人员独立复核。
- 方法：按固定坐标条件保留表单左侧标签区域，按位置组合词并去空白，检测每个完整标签是否为其中的子串。
- 观察：S038为12/13，S039为9/10，S068为5/6，S069为4/4；合计30/33。
- 未命中标签：联系人职位、付款方式、规格描述。可能涉及识别错误、换行、排序及区域筛选，不能一概归因为引擎认错。
- 限制：不是全屏逐字准确率、不是字段值正确率，也没有衡量金额、姓名、电话、模型语义理解或表格行列配对。
- 工程含义：需要原图定位、关键字段校验和纠错流程；暂不能自动将识别文本当作经营事实。

## 4. 后续样本的组织方式

每个样本有匿名编号、来源与许可范围、原件指纹、类型、用途、期望答案、关键字段、不可确定项和允许查看身份。样本脱敏要保持文字布局、金额格式或视频时间关系，不公开真实客户资料。

目前可以使用旧软件图建立界面标签样本，但不能把界面表单识别成绩当作聊天、实物视频或技术报告的效果。

| 样本组 | 应覆盖的变化 | 标注要求 |
| --- | --- | --- |
| 截图 | 小字、长图、浅色字、表格、多列、裁切、同屏多个对象 | 原文、阅读顺序、框位置、字段归属及看不清部分 |
| 聊天 | 多个发言人、历史转发、否定、修改数量、多个产品 | 发言人、消息时间、最终有效内容与前后修正 |
| 视频 | 录屏、字幕、讲话、静态重复帧、音画不同步 | 片段起止、文字与语音各自来源，重复事件标识 |
| 语音 | 人名、专业词、单位、月份、噪声和口音 | 逐字答案、听不清处、合理候选及时间戳 |
| 技术文档 | 版本、标准、单位、跨页表格、扫描与原生文本 | 页码、行列、单位、原始参数和不可直接比较项 |
| 搜索 | 公司全名/别名、单号、关键词、自然语言、无答案 | 相关来源、允许身份、期望定位、已知不相关结果 |

## 5. 效果如何记录

- OCR和转写分别记录：关键字段是否完整正确、遗漏、错误位置、人工修改量及处理耗时。字符错误率只有建立可靠逐字答案后才计算。
- 提取JSON分别记录：结构通过、内容正确、来源充分、需澄清和不可提取；不能只统计JSON合法率。
- 检索记录：固定语料及问法下的相关结果覆盖、排序、错误来源、权限过滤和原文定位。先确定k和相关性标注，再报告Recall@k等指标。
- 按需统计与展示记录：已核实规则下与独立计算的结果是否相同、筛选条件、数据时点、引用和无数据处理；不以图表好看代替数值正确。
- 性能记录：样本大小、时长、运行硬件、组件版本、配置、冷启动/热运行和失败任务；没有统一条件不比较快慢。
- 验收阈值在样本和业务影响明确后再定，不能用宣传准确率或临时拍定的百分比冒充公司要求。

## 6. 计划中的边界和失败样本

| 情况 | 拟检查的行为，不代表已实现 |
| --- | --- |
| 低清或截断的金额 | 明确无法确定，展示原件位置；不猜补金额 |
| 两个客户名相似 | 显示候选及证据，不自动合并正式客户 |
| 同一视频重复画面 | 可保留多个来源片段，避免重复形成业务事实 |
| 无讲话或无字幕 | 不编造转写；按实际信息缺口继续处理 |
| AI返回合法JSON但客户不匹配 | 业务核对失败或进入待核实，不因结构通过而正式录入 |
| 员工请求越权资料 | 业务查询、检索、原件下载及缓存结果均按同一权限处理 |
| 模型或OCR超时 | 有明确任务状态、重试与取消规则，不重复入账 |
| 用户确认前数据或权限已变 | 业务服务再次验证，不使用过期草稿直接覆盖 |
| 看板缺少数据 | 说明缺少什么，不能填0冒充真实结果或生成虚构趋势 |
| 报表被导出 | 文件权限、有效期及已下载副本管理按公司规则处理，不能假定可远程收回 |

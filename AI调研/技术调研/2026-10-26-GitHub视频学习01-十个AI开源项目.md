## 最值得留下的设计方法

1. **岗位能力包**：按销售、客服、资料、数据等场景组织“职责说明＋输入/输出＋受控工具＋已有公司规则”，共用授权、来源和审计。参考 knowledge-work-plugins 的结构，不直接拿通用财务/合同流程冒充公司制度，也不是另建十一个互相不通的机器人。
2. **有来源的分层记忆**：先返回短索引和引用，再按需要取时间上下文与原细节；记录来源、revision、适用项目和被替代关系。原件/公司规则、用户偏好和助手总结继续分开，任务进度仍由任务库管理。当前 Memory/Beads/Hardline 已各有职责，不因看到新记忆产品就替换。
3. **面向审阅的图解**：总图先展示员工入口、原件/草稿/确认、有效记录、授权查询及老板输出；技术部署再分图，颜色只表达状态，不用精美动画暗示功能已经实现。diagram-design 的 HTML/SVG 和导出可作后续候选，离线采用系统字体。
4. **任务过程可见、结果可复核**：OpenMontage 的分阶段产物、成本记录和恢复检查点可启发小隆的办公任务进度。有费用/外发/不可逆动作展示范围与预览；已授权本地可逆工作继续推进，不把所有普通步骤都改成反复请示。
5. **用资源总账核对低显存宣传**：AirLLM 的逐层读取是真正的实现思路，不能据此省略磁盘、内存、初始化和响应速度。其现 README 对某 125B 路线列出约 360GB checkpoint 磁盘和特定依赖，对本机 8GB GPU/32GB RAM 不作能跑所有模型或交互可用保证。当前无需为管理系统下载这些大权重。

## 需要纠正或保留的说法

- “能逆向任何 App”“直接能加工”“AI 自动值班修复”等是视频/项目能力概述。REA 取决于目标和可用分析引擎；CAD 的尺寸/材料/公差/工艺仍需负责人核验；OpenSRE 的 public alpha 不等同长期可靠运行。
- “本地数据库记忆”不等于整个观察/摘要过程都离线。当前 claude-mem README 的安装路径可涉及账号和托管观察服务，需明确选择与资料边界；自动采集也不能跨越公司授权。
- free-claude-code 的 GitHub API 许可识别为 NOASSERTION，本次实际 LICENSE 明示 AGPL-3.0-only，不能写成无许可证或 MIT。Claude-mem 本次 LICENSE 为 Apache-2.0；历史说法不能代替当次版本。
- 本轮实际核查 10 个仓库均未归档，pushed_at 分别记录在项目外 index.json；该时间不代表发行版修复或生产质量。README 内容 blob SHA、许可证 URL/文本/SHA256 均已保存。未装上述十个项目、未执行其安装命令、未复制其实现代码、未验证它们在本机的项目功能，也未改变正式开发阶段。

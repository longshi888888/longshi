| --- | --- | --- | --- | --- |

| 原件存储与目录 | 保存图片、视频、语音和文档，表达文件夹关系，管理版本及访问 | 对象存储本身不承担完整的业务关联或权限决策 | 原文MinIO路线保留为历史候选；比较受控文件系统、维护中的S3兼容方案等，见后续核查 | 层级、重名、空目录、大小、预览、断点上传、访问链接及恢复 |
| 文件预处理 | 识别类型，提取已有文本；视频按需要拆音轨和画面 | 不负责理解业务规则 | 原文文档解析候选 Docling；视频处理候选 FFmpeg | 格式、编码、时间戳、重复帧、失败恢复、资源占用及部署 |
| 文字及文档识别 | 从截图、扫描图或视频帧提取文字，必要时解析版面与表格 | 不负责最终确定客户身份或金额事实 | 原文候选 PaddleOCR；本次 Windows OCR 仅作材料整理基线 | 中文小字、表格、低清图、金额日期、批量性能及错误定位 |
| 语音识别 | 将老板指令、语音文件或视频讲话转成带时间信息的文本 | 不等同于指令授权或业务理解 | 原文候选 Whisper/FunASR；本轮查阅 FunASR 官方说明 | 普通话、口音、专业词、姓名、月份、噪声；流式与文件转写分别测试 |
| 大模型服务 | 理解问题，抽取候选字段，生成受约束JSON、分析与展示计划 | 不拥有正式数据库写权限，不决定金额、审批或账号权限 | 原文候选 DeepSeek/Qwen 等接口及统一网关；暂不选定具体模型 | 任务准确性、云端数据边界、拒答/追问、成本、延迟、服务失败和模型切换 |
| 业务接口及校验 | 鉴权、数据范围、JSON结构、业务规则、正式录入及审计 | 模型生成的身份、SQL或操作名不能覆盖服务端授权 | 原文候选 FastAPI + Pydantic；需另落实认证与授权机制 | 非法字段、缺失来源、重复提交、并发、过期权限及审计 |
| 统计与数据服务 | 按明确规则筛选、计算与聚合，返回可追溯结果 | 不能靠模型临时猜测指标定义或手算正式经营数据 | 业务查询/聚合服务，具体计算方案待业务量核实 | 数量与单位、金额与币种、业务时间、归属、撤销退货和跨期 |
| 按需仪表与报表 | 展示查询结果、筛选条件、来源、摘要，支持多种仪表 | 图表库不提供原始业务事实，也不能绕过权限 | 原文候选 React + ECharts 等；具体展示协议待设计 | 动态维度、指标白名单、明细回溯、数据缺失提示、导出与性能 |
| Windows 客户端 | 登录与业务操作、上传、预览、语音入口、本地文件处理及安装升级 | 不能把服务器凭据或全部公司数据随意放进员工电脑 | 原文候选 Tauri 2 + React/TypeScript | 目标Windows版本、架构、安装体积、组件封装、进程权限、升级回滚 |
| Office 文件处理 | 生成、读取及导出表格或文档，按需计算公式和转换格式 | 不能替代业务规则或把大模型输出当可执行任意代码 | 原文候选 openpyxl、Polars、LibreOffice/UNO | 真实模板、公式及PDF效果、中文字体、进程隔离、打包与许可证 |
| 异步任务与运维 | 长视频处理、重试、限流、任务状态、备份、日志与监控 | 不能无限重试、重复入账或跨权限复用结果 | 原文候选Redis/Celery；补查版本许可与平台，Valkey等替代组合兼容性待测；不默认在Windows运行Celery | 重复任务、失败、取消、容量、监控及恢复 |

“文本数据库”“检索索引”“原件存储”是逻辑职责，不预设一定要分成多个数据库产品。选择是否共用基础设施，要结合规模、维护能力和恢复要求决定。

## 2. 已从官方资料核实的职责范围

- PostgreSQL 全文检索包含分词解析、词典与索引等环节。**本项目推论**：中文与longshi专有词需要实际验证，不能把“支持全文检索”当作中文效果已经达标。[官方全文检索说明](https://www.postgresql.org/docs/current/textsearch-intro.html)
- pgvector 提供向量相似度检索，并说明可与 PostgreSQL 全文检索组合。它不替项目生成合适的文本向量，也不证明业务命中率。[官方仓库与混合检索说明](https://github.com/pgvector/pgvector#hybrid-search)
- pg_trgm 提供字符三元组相似度及索引能力，适合纳入字面相似检索候选；效果须用公司名、单号及中文样本检查。[官方 pg_trgm 说明](https://www.postgresql.org/docs/current/pgtrgm.html)
- Amazon S3 普通桶使用对象键与前缀表示文件组织，并非传统文件系统的完整目录层级。**本项目推论**：若采用这类存储，文件夹、移动、版本与授权的产品语义需要另行设计；此处不意味着选用 AWS 或认定所有兼容产品行为相同。[官方目录语义说明](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-folders.html)
- PaddleOCR 提供文字识别和文档解析能力，供截图及文档样本评估；本轮没有运行其模型，不引用公开榜单当作longshi样本的准确率。[官方 PaddleOCR 仓库](https://github.com/PaddlePaddle/PaddleOCR)
- FFmpeg 负责音视频转换和处理，可作为音画预处理候选；具体抽帧和音轨流程待样本验证。[官方 FFmpeg 文档](https://ffmpeg.org/ffmpeg.html)
- FunASR 提供语音识别及相关处理能力；工具源码与预训练权重的许可需要分别核对。[官方 FunASR 仓库](https://github.com/modelscope/FunASR)
- Pydantic 校验输出的类型与约束，不保证业务内容真实。**本项目推论**：客户匹配、金额来源、权限和人工核对仍需独立处理。[官方模型说明](https://pydantic.dev/docs/validation/latest/concepts/models/)
- PostgreSQL RLS 可约束行访问，但表所有者、超级用户或特权角色存在绕过条件。**本项目推论**：不能给AI关联服务数据库高权限角色后只依靠提示词约束。[官方行安全说明](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)
- Tauri 支持随应用封装外部程序，并有相应调用权限配置。可作为本地处理组件打包研究入口，仍需实际验证整个安装包。[官方 sidecar 说明](https://v2.tauri.app/develop/sidecar/)

未完成版本、依赖、模型权重许可、离线分发及安装验证的候选，不进入“已定选型”清单。其余候选来自原始人工调研文件，本轮尚未全部重新核实。

## 3. 按输入类型设计验证样本

| 输入 | 拟验证流程 | 核对重点 |
| --- | --- | --- |
| 直接文字 | 保留原文→识别业务对象→候选字段JSON | 别名、时间、单位、否定语句、重复提交 |
| 聊天截图 | 保留原图→OCR→对话顺序→业务字段草稿 | 发言人、截断上下文、公司名、价格、日期、来源框 |
| 扫描或电子文档 | 按文件类型提取文本/版面→表格字段→来源页 | 跨页表格、单位、标准、修订版本、扫描质量 |
| 录屏或带字幕视频 | 保留视频→按需要抽帧→OCR去重→时间片段 | 页面变化、重复画面、字幕与界面文字、片段定位 |
| 带讲话视频/语音 | 提取音轨→转写→必要时关联画面→候选字段 | 姓名、材质、数字、口音、时间戳、音画是否互补 |
| 无明确文字的实物视频 | 根据真实用途评估是否需要视觉模型 | 不能预设OCR就能理解产品外观或质量；先核实场景 |
| 整个文件夹 | 清点目录→上传与保存层级→逐文件处理→聚合关系 | 重名、空目录、附件关联、处理失败、部分重试 |

本轮仅有旧系统 PNG 截图和一份 TXT 原文；没有真实视频、音频、复杂技术文档或整文件夹录入样本，因此不能宣称相关效果已经验证。

## 4. 本轮 Windows OCR 的验证记录

- 70张原图均成功返回机器文本，共2160个OCR行记录；原始来源、哈希、尺寸、词框及全文保留。
- 对全部页面进行了页面/菜单/字段初核；其余字符与数值不声明全量人工核定。
- 原图不变，预处理图和工具脚本放在项目外；本次未安装生产OCR、数据库或模型组件。
- 观察到“落单”等业务词、公司名、小字体和数字存在识别错误，多列阅读顺序也会错乱。当前不具备将机器结果直接写为正式业务记录的依据。
- 没有标注好的逐字真值数据，因此不报告准确率百分比。下一步用脱敏业务样本建立核对答案，分别评估关键字段正确率、遗漏、处理耗时和人工修改量。
- Windows OCR 仅用于本次材料研究；不会据此认定它是本产品最终开源识别引擎。
- 后续已对4张关键表单的33个标签作视觉转录与有限区域检测，规则命中30个；不是全局准确率或字段值正确率，详见 [实际记录](../技术验证/验证计划与验收样本.md)。

## 5. 权限与JSON的验证场景

1. 普通员工请求另一业务员客户、利润或原始附件：服务端按已定义权限处理，检索、缓存和原件下载规则一致。
2. 文本或附件包含“忽略权限、修改数据”等指令：作为资料内容处理，不获得系统操作权限。
3. AI输出未知动作、SQL、脚本、自称老板或填写他人账号：不能作为执行依据，身份来自真实会话与服务端鉴权。
4. JSON格式正确但金额、客户或时间缺少证据：标记缺失与待核实，不能因结构通过就正式录入。
5. 多次上传同一截图或视频重叠片段：允许重新识别与保留来源，避免重复生成正式业务事实。
6. 文件或客户权限撤回后：搜索片段、向量结果、缓存、生成报表和下载入口按规则更新，不只隐藏主列表。
7. 模型服务失败或不可用：已确定的普通业务操作和统计仍能运行；模型辅助任务有明确失败状态。

这是拟验证的系统行为清单，不是已经实现或测试通过的功能。

## 6. 最终技术文档需要回答的项目

每项确定技术写清：业务职责、选择理由、替代方案、确定版本、开源与模型许可、输入输出契约、部署位置、权限与凭据、资源需求、失败处理、升级与回滚、备份恢复、测试样例及验收方法。

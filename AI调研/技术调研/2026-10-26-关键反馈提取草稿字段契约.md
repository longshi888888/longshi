# 关键反馈提取草稿字段契约

2026-10-26，3号，`lsr-nov`。revision 1；supersedes：无。proposed纸面契约。复用[KF](2026-10-26-关键反馈到订单进度的可信链路补查.md)、[五部门融合r2](../产品经理调研/2026-10-26-五部门资料融合与系统设计增量.md)，未重读原件。

## 契约边界

服务在AI输入前检查当前对象、动作、字段及外送范围，仅供获准片段；无法安全分片则不送整件。授权上下文由服务生成。人工可绕过AI，类别上报不统一。

草稿只供核对。正式确认、审批、验收及状态写入字段不在白名单，出现则拒收；资料声称“已批准”仅作待核主张。

## 字段

- 草稿ID、版本、来源ID/版本、提取器版本：由服务记录；新提取不覆盖旧核对。字段与对象候选各自引用证据片段。
- 片段定位：文字段/字符区间、图片页/坐标及尺寸、页签/单元、音频时段；说明坐标/区间约定。没有录音不得填音频定位，识别文字回指原图。
- 主张：保留原措辞、否定、疑似、计划及数量单位/范围/增量或累计口径。`basis`区分`source_quote`、`employee_retelling`、`ai_inference`；原话仅指该来源所载文字，不保证发言身份或事实真实。人工补充/可靠任务上下文另记依据，不冒充原文。
- 多对象：区分文本提及、获准系统候选和关联状态；未核实为`unconfirmed`，不因同名/预选绑定。各项引用片段，不强制挂订单。
- 缺失/矛盾：未知值用`null`并记缺失原因；相斥主张保留双方证据及待核原因，不由模型选胜者。加工结果与质量待核可并存。发生/发言/提交时间分开，计划时间不填实际时间。
- 核对记录：待核/部分核对/已核对、逐字段选用或改写、依据及操作者/时点由服务留痕；“已核对”只表示字段处理，不表示业务生效。提交核对结果时重查权限及草稿版本。模型置信度可空，仅描述提取判断，不充当业务真实性、对单正确或生效门槛。

## 全虚构JSON

均虚构；省略服务审计字段，非生产请求。定位为复述段号，不是录音原话。

```json
{
  "kind": "extraction_draft",
  "revision": 1,
  "source": {"ref": "demo:s1@1", "kind": "employee_retelling"},
  "fragments": {
    "p1": {"loc": "paragraph:1", "text": "甲批可能加工完了"},
    "p2": {"loc": "paragraph:2", "text": "乙单明天安排"}
  },
  "items": [
    {"mention": "甲批", "association": "unconfirmed", "claim": "可能加工完成", "basis": "ai_inference", "evidence": ["p1"], "occurred_at": null},
    {"mention": "乙单", "association": "unconfirmed", "claim": "计划安排", "basis": "ai_inference", "evidence": ["p2"], "occurred_at": null}
  ],
  "missing": ["数量及范围未明", "发生时刻未知", "明天缺日期锚点"],
  "conflicts": [],
  "review": {"status": "pending", "patches": []},
  "model_confidence": null
}
```

`conflicts: []`不证明无冲突；对象提及不是系统ID。复述与AI归类分开，不产生完成事件。

## 失败检查候选

1. **KF-02：** 数量模糊时不得补0/计划量；无图中单号但有可靠上下文时，可核归属，仍不补猜结果。
2. **KF-03：** 两对象不得全挂当前单；受限对象不扩展系统候选或整件外送。
3. **KF-04/05：** “现在6件”不得直接加总；质量待复核不自动撤销加工结果。真正相斥主张不得只留高置信一项。
4. **KF-06/07：** 晚传旧图不改成最新现场；“明天”无锚点不猜日期，复述不伪造音轨/客户逐字证言。
5. **KF-01/08：** 已核对或高置信不得触发正式确认/验收；旧版本、撤权或夹带生效字段时不得静默写入。

仅核文稿/JSON，未执行验收。关联键、数量/完成规则、采信来源、权限/外送范围及定位适配待核，模型分数不替代门槛。

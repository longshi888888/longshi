## 2 后台工作流怎样用于我们的项目

视频的操作顺序是：读Axure原型的目标、功能、字段和状态；分析视觉参考；做首页主视觉并人工调整确认；建立设计变量和可复用组件；按原型批量搭页；每批沉淀组件和已纠正问题；总结设计验收标准供后续会话读取。它强调只从原型继承业务内容，不复制旧布局，也不能擅自补指标、卡片或操作。

| 视频方法和定位 | longshi采用方式 | 需要保留的区别 |
| --- | --- | --- |
| 原型分析，0:47—1:17、4:54—5:54 | 先从基础功能迁移清单及对应旧页/规则，列页面、字段、动作、状态、弹层与缺口；资料不足标待核 | 公司业务依据优先，旧页也可能不完整；不能由AI补成制度 |
| 参考图与主视觉，1:17—2:55、5:54—7:27 | 先选适合业务密度的风格，再做有代表性的列表/表单/详情及状态；确认后扩展 | 首页不一定最有代表性。视频的背景图、玻璃效果是作者案例选择，业务表格不必照搬 |
| 变量与组件，2:55—3:16、8:26—10:13 | 沉淀导航、筛选、表格、字段、按钮、分页、状态与错误提示，约束文字/颜色/间距及各状态 | 组件既要视觉一致，也要含义一致；复用以后修改一个组件须检查受影响页面 |
| 每批回填与验收，3:16—4:29、7:45—8:10、10:34后 | 按字段动作矩阵查遗漏和擅增；记录错因、纠正和验证方式，下一次先读适用规则 | 对话自动总结只是候选，需回读确认；不能把一次审美偏好写成跨项目硬规则 |

[当前Figma官方文档](https://developers.figma.com/docs/figma-mcp-server/)区分读取设计上下文与向画布写入；当前画布写入有远程服务及席位/位置等条件。视频没有证明本机当前账号具备相同能力。本轮没有安装或连接Figma，也没有向云端发送公司原图；采用其工作顺序不要求先采用其整套工具。

## 3 二十条规则的业务界面用法

下表是视频内容的简要理解和本项目的应用判断，数值例子不直接升级为公司规范。

| 时间 | 视频规则 | 在longshi中怎样试用及避免误用 |
| --- | --- | --- |
| 0:55 | 选定界面个性 | 用克制、易读的字体、主色、圆角和文案保持一致；选择仍看实际页面效果 |
| 1:14 | 先灰度后上色 | 先检查分组和主次是否成立，再用颜色加强重点，不能靠整页彩色卡片弥补结构 |
| 1:32 | 字号不是唯一层级 | 组合字重、颜色和间距，避免辅助文字小到读不清；不能把所有正文都淡灰 |
| 1:50 | 弱化周围突出重点 | 导航选中项及主要动作更容易识别；次要内容仍需可读、可发现 |
| 2:06 | 删掉不必要的展示标签 | 只在含义自明时去冗余；客户归属、金额、件数、单位、来源时点及输入标签要保留 |
| 2:27 | 按钮有主次 | 主动作、次动作、辅助动作区分；删除/撤销等风险仍清楚说明，并按实际规则确认和授权 |
| 2:50 | 先多留白再收紧 | 以分组清楚为目标试间距，再比较表格可见行数与查找效率，避免后台页面被空白撑散 |
| 3:08 | 不必填满屏幕 | 短表单不强拉全宽；多列表格也不为了居中变窄到看不全 |
| 3:29 | 组间距大于组内距 | 标签更贴近所属字段，筛选组和结果区分清楚，减少把数量/单位或上下记录认错的机会 |
| 3:49 | 手机不等比缩桌面 | 在实际窄屏重排标题、字段和动作；关键字段/操作可达，表格必要时提供适当滚动或详情 |
| 4:12 | 行长与行高配合 | 长说明和备注适度限宽；视频英文字符数/行高仅参考，中文、数字表格和字号须分别看 |
| 4:34 | 大小文字按基线对齐 | 标题与辅助链接、数值与单位需要检查基线；图标、头像和整块控件不机械全改baseline |
| 4:53 | 需要完整颜色层次 | 中性色、品牌色、语义色有可复用档位；具体多少档按组件需求选择，不硬凑8—10档 |
| 5:21 | 无障碍也能好看 | 状态可试浅底深字；对实际前景/背景测对比，视频示例的比值不能当我们的检测结果 |
| 5:46 | 不只靠颜色传信息 | 待核/异常/通过写出文本，图表和涨跌配文字、箭头或形状；箭头不能替代业务口径 |
| 6:05 | 用少量强调色边线 | 可用于选中导航或提示，不给每块卡片都加强调条；语义仍须明确 |
| 6:26 | 图上文字先处理背景 | 真有配图时调整遮罩、图层/裁切并核对比；不为采用技巧给业务页增加装饰背景 |
| 6:47 | 素材有合适尺寸 | 图标按目标尺寸选型，示意图突出关键局部；矢量放大不糊也不保证线条比例好看 |
| 7:11 | 边框适量 | 比较留白、底色、少量分隔线；密集行列的关联仍应清晰，输入边界和焦点不能因此消失 |
| 7:32 | 设计空状态 | 区分尚无数据、筛选无匹配、无权、加载中和失败，给相应可用动作；不能将失败显示成0条 |

视频最后建议分析优秀界面及动手复现。后续练习优先用我们自己的虚构业务例子，分析层级和结构，避免复制品牌素材或把任意演示字段加入需求。

## 4 需要核对的三类说法

[W3C文字对比标准](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)对普通文字通常要求至少4.5:1，大文字通常3:1，存在禁用/装饰/标识等例外；大文字有实际尺寸定义，不是看起来粗就随意按3:1。视频中两组彩色标签本来均显示合格，后者是风格和更高对比的选择，不能把左图说成不合规。本轮只核标准，没有测我们的页面是否达标。

[W3C颜色使用说明](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)要求不能只用颜色区分必要信息。[输入标签说明](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html)要求输入有适当标签/指引；程序可读名字和使用者能看见的指引也不能简单互相替代。因此视频第5条只用在可去冗余的展示内容，不删表单含义、单位和必要说明。

三秒耐心、若干档灰色、英文行长等是视频转述的经验说法；本轮没有相应用户实验。第19例右侧仍有细行分隔，并非所有线全删；第14/18例左侧也不是一律错误。手机标题例画面确为四行。采用原则应按实际任务比较，不能把示例参数当普适门槛。

## 5 下一次类似任务怎样试用比较

用户已明确：发来的视频在类似任务中要尝试适用技巧，再根据结果选择。执行时先选一个小而代表性的页面/操作，固定同一数据、功能、目标屏幕和输入条件；保留当前做法作对照，只引入能解释作用的技巧，避免同时大改到无法判断原因。

候选纸面例子是当前P02客户列表/档案/建档，来源为[基础版关键页草图](../../软件开发计划+施工清单/页面与原型/基础版关键页面草图.html)r2、B01—03及对应资料；可比较层级/分组/按钮主次/状态文字，仍不把草图字段定为最终制度。基础版已有19组页面目录、8组重点布局和8个候选逻辑批次，不由本轮学习重新排首批范围。

| 检查维度 | 对照时保留的可核对内容 |
| --- | --- |
| 业务一致 | 同一字段、单位、来源、时点、动作和状态；不能用删字段或新增AI假数据换来好看 |
| 信息查找 | 在同样记录里找同一客户/归属/异常和主要动作，记实际误认、漏看和需要的操作；没有计时就不写提速百分比 |
| 阅读与布局 | 同宽度/缩放截图核行列、长中文、长编号、大数/零/未知；目标Windows与获准手机入口分别看 |
| 状态与操作 | 空数据/无匹配/无权/加载/失败/保存中等适用状态分别检查；真实运行时再查键盘、焦点、对比及提交结果 |
| 成本和影响 | 记调整次数、发现的问题、耗时及组件改动影响；改进不明显则调小、换方法或保留原方案 |

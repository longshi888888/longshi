# 老板查询：结构化结果与展示契约草案

2026-10-26；revision 2；1号；proposed设计。supersedes r1：补固定结构化提案到受控柱图的有限实测状态，r1保全项目外，原示例和未验边界保留。承接[主链r6第11/12节](../产品经理调研/2026-10-26-关键反馈到老板查询设计草案.md)与[授权/引用实测](../技术验证/2026-10-26-合成权限与AI资料边界实测.md)。不是已实现产品API、数据库结构、公司统计制度或开发批准。

## 要解决的问题

老板问“这张单加工多少了”，AI不能把计划、旧版和重复摘要相加，也不能把“加工完成”说成“检验通过”。系统查询应先返回可核对的数据包，再让界面和AI解释它。员工已在来源核对/阶段确认时提供过的信息，由系统关联带出，不为老板查询再填一张汇报表。

## 谁提供什么

| 层次 | 允许提供的内容 | 保留在服务端的控制 |
| --- | --- | --- |
| 用户/AI查询意图 | 允许的查询种类、可靠已选对象引用或待消歧条件、时间/指标意图 | 主体从真实会话取；对象范围、字段、规则版本及当前权限不由模型授予；不开放任意SQL/代码 |
| 业务查询结果 | 获准对象、字段值、单位、范围、有效版本、所用口径、数据时点及覆盖说明 | 只取当前有效正式记录；按定义聚合；片段、记录、字段和原件动作各自核权；缺定义不编算法 |
| AI解释候选 | 引用本次返回项，说明已知和未知；可建议允许的图表类型 | 新增事实不能冒充系统字段；数量、状态、单位及范围须对照受控结果检查；自由文字的语义正确性仍待验证 |
| 界面/图表 | 数据点引用服务结果字段，标题/单位/过滤条件和时点明确，支持允许的明细回看 | 不执行模型脚本/回调/外部资源；不让模型替换数据点、补0或推算未经定义的完成百分比 |

这里的“当前”必须说明是当前查询可用的有效版本，不承诺实时反映现场。发生时间、记录时间、查询时间不同；未知发生时间不取上传时间代填。异步视图应标明更新时点/滞后，不能只挂“实时”字样。

## 结果应携带的最少信息

| 信息组 | 候选内容及含义 |
| --- | --- |
| 本次结果 | 契约版本、结果引用；服务端绑定请求和受控执行上下文。引用不是访问凭据，重开仍核当前权 |
| 查询范围 | 可靠对象/范围、已解析的条件、当前或明确历史用途；未能确定“这张单”时先澄清，不按相似度第一名绑定 |
| 口径 | 已定义的指标及规则版本、计量单位、时间范围/时区；不把虚构加工数量定义当公司业绩定义 |
| 数据项 | 正式记录/字段引用、值、单位、对象/批次/阶段范围、有效版本；不同工序、批次、单位不擅自相加 |
| 时点与覆盖 | 数据快照/视图版本及已知数据时点；完整性仅相对于明确的获准查询范围，不能外推全公司无遗漏 |
| 依据入口 | 只有当下允许展示的定位/回看引用；记录可见不强制开放原始附件；不附权限名单、隐藏证据计数或拒绝原因 |
| 未知与异常 | 缺定义、缺可靠关联、数据冲突、更新中或处理失败等可安全说明的原因；无法区分无数据与无权时用中性外形 |

服务端详细审计另记实际主体、策略/数据版本、使用规则与内部拒因；员工响应不照搬审计对象。故障时不把上次回答换成当前结果，历史结果能否重开由当前权及有效性决定。

## 同一合成例子，数据够到哪就说到哪

复用[原固定夹具](../技术验证/2026-10-26-检索验证合成样本.json)，只说明纸面契约。员工A仍有`demo:result-a@2`记录读权，即使其证据片段已撤权，也可得到允许的记录字段；不因此带出受限源文。本例不宣称知道检验结果、整单完成率或真实发生时间。

```json
{
  "schema_version": "query-result-proposed-1",
  "result_ref": "demo:query-result-1",
  "status": "result",
  "scope": {"order_ref": "DEMO-A-001", "view": "current_in_fixture"},
  "metric": {
    "definition_ref": "demo:fixture-confirmed-processing-quantity-v1",
    "definition": "仅本虚构快照本单当前有效加工确认数量",
    "unit": "件"
  },
  "items": [
    {"record_ref": "demo:result-a@2", "field": "quantity", "value": 2, "unit": "件"}
  ],
  "snapshot_ref": "demo:snapshot-1",
  "data_time": null,
  "data_time_note": "固定夹具未给实际发生或业务更新时点",
  "coverage": "仅此虚构快照内已授权的本单记录，不代表公司全量",
  "source_links": []
}
```

`result_ref`和指标定义引用是新增的虚构契约占位，不是原夹具已有字段。`source_links`空仅表示本次数据包不含来源链接，不代表没有依据；不向用户暴露是不存在、未加载或无权限。正式产品还须核字段授权、记录粒度与批次/时间映射，不能把`@2`字符串本身当通用版本实现。

候选可控展示为：“本虚构快照中，这张单当前有效加工确认数量为2件；此结果未提供检验结论及实际更新时间。”系统不应把它扩成“6件已检验通过”。老板查整个虚构快照时，只有在有权取得两条记录并使用同一定义后才可得2+3=5；不能把员工单记录结果换标题当全公司总数。

## 下一次验证应检查什么

以下是沿用EXP-06/08的验收预期。r1只检查示例JSON、夹具引用和算术；接续已执行[固定结构化提案到受控柱图实验](../技术验证/2026-10-26-查询结果到图表的数据一致性实测.md)，具体范围见下节。真实AI自由解释、问句路由及完整系统仍未验证，不能把下表所有预期一起标通过。

| 输入变化 | 预期边界 |
| --- | --- |
| 同一回答把2改6、件改元、加工改检验 | 对照受控结果字段拒绝作为正式展示；不能只检查JSON或引用存在 |
| 只有计划/规范，无正式结果 | 可展示获准资料候选及其性质，不显示实际已完成；空值不补0 |
| 只有部分获准数据，却要求全部合计 | 先按明确获准范围给受限范围结果或说明无法得全量；不返回隐藏记录数，不冒充全公司总计 |
| 实际全部获准范围确已查全且无记录 | 只有定义允许且覆盖证据充分，才能给该范围的0；搜索无命中不满足这个条件 |
| 数据/权限变更后重开或渲染 | 重新核权与版本；过时结果带时点或重新取数；本轮没有实现并发原子性 |
| 指代/人名/业绩定义不明 | 只澄清影响本次结果的具体条件，不要求员工重填日常资料，不猜业务定义 |
| 图表配置另塞数据、脚本或越权字段 | 图表仅绑定获准结果字段；不执行代码，不把不可访问项变作图注或隐藏数据点 |

后续由明确字段比较可验证的部分先做小实验；自由解释与来源语义的支持程度另设固定答案，不用本例文本硬编码一个“真值判断器”。在实际技术栈和公司口径未定前，不扩大为完整AI工作流实现。

## 本轮实际收敛

24例固定提案的结构与绑定已执行：8例合法字段不匹配拒绝、5例额外配置结构拒绝、2例未知空不补0，过期/缺指标/缺指代各1；6例可导出数值含正确结构外带假叙述的负照。107项适用输出对照一致，不代表107个案例或6个真实答案已证真。身份、获准范围、口径及覆盖是实验可信前提，未验证实际业务查询产生过程。

引用绑定路径只让提案选择已有结果/字段及允许的展示，服务生成行值、单位、范围、标签；echo对照另检2变6、单位、指标、记录及版本/范围不符。后者仅用来验证字段可比较，不作为产品必增接口。实际两个引用绑定结果已传给ECharts 6.1.0并渲染SVG，保存的dataset、标签及限定柱形高度一致；不是图表交互/字体/WebView验收。

候选倾向是让AI少重写一份数字，权威数值/状态按服务结果绑定；图表选型仅承担渲染。自由解释没有因此获得事实确认，任意正文不自动进入权威标题或数据点。原始图表库拿到不可信6件仍能画出来，是保留的职责反例。柱图白名单只用于本轮小实验，不限制公司未来不同仪表。
